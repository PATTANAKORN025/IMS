# ระยะที่ 2 — การเพิ่มความเสถียรของแดชบอร์ด LDI ระดับโลก: รายงานเปรียบเทียบเกณฑ์มาตรฐาน

> **เก็บถาวร — ภาพรวมในอดีต, ลงวันที่ 2026-08-05** ไม่ใช่เอกสารที่มีการปรับปรุงต่อเนื่อง ตัวเลขด้านล่าง (จำนวนแดชบอร์ด, จำนวนการย้ายข้อมูล, จำนวนพาเนล ฯลฯ) สะท้อนถึงระบบตามที่เคยเป็นในวันนั้น และเป็นที่ทราบกันดีว่าล้าสมัยเมื่อเทียบกับระบบปัจจุบัน เก็บไว้เป็นบันทึกทางประวัติศาสตร์ตาม docs/archive/README.md สำหรับข้อมูลปัจจุบัน ดูที่ docs/architecture/ARCHITECTURE.md และ docs/architecture/DASHBOARD_INVENTORY.md

`phase2-baseline-metrics.md`) รายงานนี้เปรียบเทียบข้อมูลพื้นฐานดังกล่าวกับสถานะหลังจากกระแสงาน (workstreams) ในระยะที่ 2 ทั้ง 10 ส่วน ซึ่งแต่ละส่วนได้รับการตรวจสอบกับข้อมูลจริงและถูกคอมมิตแยกกัน (ดู git log `13b0317..1380e82` บน `main`)

## 4. ประตู CI/ลินต์ใหม่ (New CI/lint gates)

| ประตู (Gate)                                    | สิ่งที่ตรวจจับได้                                                                      | ผลลัพธ์ในโค้ดเบสนี้                                                                                                                                                     |
| ----------------------------------------------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tests/lint/rca-mapping-coverage.js`            | รหัสการแจ้งเตือนถูกเพิ่มในรายการหลักโดยไม่มีหมวดหมู่ RCA ที่ตรงกัน → ทำให้เกิดความครอบคลุมเป็นศูนย์โดยไม่แจ้งเตือน | ความครอบคลุม 70%, พบข้อผิดพลาดการอ้างอิงแดชบอร์ด 0 รายการ                                                                                                                                  |
| `tests/lint/query-budget-linter.js`             | พาเนลสแกนช่วงข้อมูลดิบของ `ldi_data` แทนที่จะเป็นชั้นข้อมูล CAGG                            | พบและแก้ไขการละเมิดจริง 1 รายการ (`ldi-data-readiness.json` "Telemetry Ingestion Rows by Machine" — ตอนนี้อ่านค่าจาก `ldi_data_1m.sample_count`); เหลือ 0 รายการ                      |
| `tests/smoke/query-budget-check.sh`             | การถดถอยของคำสั่งที่ร้ายแรง (cartesian join, index หายไป, N+1)                     | ทำงานในขั้นตอน integration-chaos ของ CI, ใช้งบประมาณ 2000ms (จงใจให้มีเวลาเผื่อไว้มาก — ดูที่ส่วนหัวของสคริปต์สำหรับเหตุผลที่ตัวเลขที่เข้มงวดไม่สามารถนำไปใช้กับสภาพแวดล้อมที่มีปริมาณข้อมูลต่ำของ CI ได้) |
| `tests/playwright/ldi-responsive-regression.js` | ข้อผิดพลาดในการเรนเดอร์พาเนล, พาเนลแบบ "No data", Andon ล้นหน้าจอ                                  | ผ่าน 15/15 รายการครอบคลุม 5 แดชบอร์ด × 3 ขนาดหน้าจอ                                                                                                                                |

**ข้อสังเกตเกี่ยวกับขอบเขตที่แท้จริงของ "การเรนเดอร์ P95 < 300ms":** สิ่งนี้ถูกบังคับใช้เป็นงบประมาณของเวลาในการประมวลผลคำสั่ง (การเอ็กซีคิวต์ SQL ฝั่งเซิร์ฟเวอร์) ไม่ใช่เวลาในการวาดบนเบราว์เซอร์อย่างเต็มรูปแบบ (เครือข่าย + การติดตั้งพาเนล Grafana + การเรนเดอร์ React) ไม่มีระบบการทดสอบเวลาในการเรนเดอร์แบบ end-to-end เต็มรูปแบบใน repo นี้; การสร้างสิ่งนั้นจะต้องใช้การติดตั้งเครื่องมือเพื่อวัดเวลาในฝั่งเบราว์เซอร์ (เช่น Playwright + CDP network timing) ซึ่งไม่ได้ถูกสร้างขึ้นในรอบนี้ คำสั่งทั้งหมดที่สุ่มตัวอย่างมามีเวลาต่ำกว่า 300ms มาก; แต่เวลาพร้อมแสดงผลบนหน้าจอจริงของพาเนลจะสูงขึ้นเล็กน้อยเนื่องจากโอเวอร์เฮดของ Grafana/เครือข่ายที่ไม่ได้ถูกจับภาพไว้ในที่นี้

## 5. ระบบการออกแบบ (Design system)

- ขอบเขตของ `docs/GRAFANA_DESIGN_SYSTEM.md` ขยายจาก 3 แดชบอร์ด (NOC/Engineering/Capacity) ไปยังทั้ง 9 แดชบอร์ด, ทำให้มีเอกสารอ้างอิงของชุดสีแนวไซเบอร์พังก์ที่มีอยู่เดิมของแดชบอร์ด LDI (ส่วนที่ 2.1a) อย่างเป็นทางการ ในฐานะคู่ขนานที่ได้รับการยอมรับกับชุดสีดั้งเดิมของ NOC แทนที่จะบังคับให้เปลี่ยนสีพาเนลที่ได้รับการตรวจสอบแล้วประมาณ 230 รายการ
- ประสานการใช้สีที่หลุดกรอบซึ่งมีอยู่ก่อนหน้า 33 กรณี (รูปแบบสี `#00E5FF`, `#EF4444`, `#FACC15`, `#22C55E`) ให้สอดคล้องกับแบบแผนหลักของ LDI — ถือเป็นการเปลี่ยนแปลงที่เกิดขึ้นจริง, บางส่วนเพิ่งถูกนำเข้ามาในเซสชันนี้, ตอนนี้ทั้งหมดมีความสอดคล้องกันแล้ว
- ขยาย `ALLOWED_HEIGHTS` ใน `dashboard-linter.js` (`1,4,5,6,8,10,16`) เพื่อให้ตรงกับความสูงของ KPI-stat แบบแผนในส่วนที่ 5.2 (h=4) และความสูงของ Gauge (h=6) ซึ่งตอนนี้ถูกใช้งานจริงทั้งคู่

## 6. สิ่งที่ไม่ได้ครอบคลุมในรายงานนี้

- ค่า P95 ของเวลาในการเรนเดอร์แบบ end-to-end ที่แท้จริง (การวาดบนเบราว์เซอร์, ไม่ใช่แค่เวลาของคำสั่ง) — ไม่ได้ถูกวัด
- การถดถอยทางการมองเห็นผ่านพิกเซล-ดิฟ (Pixel-diff visual regression) — ไม่มีไลบรารีจับความต่างของภาพใน repo นี้; ชุดเครื่องมือ Playwright ใหม่ทำการตรวจสอบโครงสร้าง (ข้อผิดพลาด, ไม่มีข้อมูล, การล้นหน้าจอ) แทน ซึ่งได้จัดทำเป็นเอกสารข้อจำกัดขอบเขตในไฟล์ทดสอบไว้โดยเจตนา
- มีการสร้างชั้นข้อมูล CAGG แบบ 15m/1h และยืนยันความถูกต้องแล้ว แต่ยังไม่มีผู้นำไปใช้งาน — ปัจจุบันไม่มีพาเนล LDI ใดที่มีระยะเวลาการแสดงผลเกิน 6 ชม.
