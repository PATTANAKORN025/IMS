# การวิเคราะห์คุณค่าทางธุรกิจและผลตอบแทนจากการลงทุน (Business Value & ROI Analysis)

> **กลุ่มเป้าหมาย:** ผู้บริหารระดับสูง, ผู้สนับสนุนโครงการ
> **วัตถุประสงค์:** สรุปผลกระทบทางธุรกิจ ผลตอบแทนจากการลงทุน (ROI) และการปรับปรุงทางเทคนิคที่ได้รับจากแพลตฟอร์ม IMS
> **ที่มา (แก้ไขเมื่อ 2026-08-10):** ข้อมูลทางเทคนิคด้านล่าง (จำนวนแดชบอร์ด, จำนวนคอนเทนเนอร์, จำนวนกฎการแจ้งเตือน, ผลการทดสอบโหลด, จำนวนเอกสาร) ได้รับการอัปเดตให้ตรงกับระบบปัจจุบัน ข้อมูลทางการเงิน/ROI (ชั่วโมงการทำงานของพนักงาน, การประหยัดค่าใช้จ่ายเป็นบาท, ระยะเวลาคืนทุน) เป็นข้อมูลนำเข้าทางธุรกิจดั้งเดิมและถือเป็นกรณีศึกษาทางธุรกิจ (Business Case) แรกเริ่ม

## 1. บทสรุปผู้บริหาร

**IMS** แสดงถึงการเปลี่ยนผ่านจากระบบ **การตรวจสอบด้วยตนเอง (Manual Monitoring)** ไปสู่ **การตรวจสอบแบบอัตโนมัติอย่างต่อเนื่องด้วย AIOps** สำหรับเครื่องจักร YSPhotec / LDI ในสายการผลิต PCB

ระบบใช้สถาปัตยกรรม **โอเพ่นซอร์ส (Open-Source Stack)** ซึ่งผ่านการทดสอบโหลดที่ระดับ **1,000 VUs** ในขณะที่ยังคงรักษางบประมาณความล้มเหลวที่กำหนดไว้ (อัตราความสำเร็จของไปป์ไลน์ >95% ภายใต้สภาวะโหลดแบบ Chaos ขั้นสุด)

## 2. เมทริกซ์ปัญหา → แนวทางแก้ไข

### ก่อนหน้า (ปัญหาจากระบบเดิม)

| ปัญหา | ผลกระทบ | ต้นทุนรายวัน |
| ----------------------------- | ------------------------------------------------ | ------------------------------ |
| **ความล่าช้าในการมองเห็นข้อมูลด้วยตนเอง** | ต้องเดินตรวจตราเพื่อตรวจสอบมาตรวัดทางกายภาพ | พนักงาน 2 คน × 4 รอบ = 8 ชม./วัน |
| **การตรวจจับเวลาหยุดทำงาน (Downtime) ช้า** | ใช้เวลา 2-4 ชั่วโมงในการตรวจพบความล้มเหลว | ยอดผลผลิตที่เสียสะสม |
| **การป้อนข้อมูลด้วยตนเอง** | ข้อผิดพลาดจากมนุษย์ (Human error) ~15% | ไม่สามารถติดตามแนวโน้มได้ |
| **การบำรุงรักษาเชิงรับ (Reactive)** | รอให้เกิดข้อบกพร่องก่อนซ่อมแซม | เวลาหยุดทำงานที่ไม่ได้วางแผน |

### <img src="../../../docs/assets/icons/check-circle.svg" width="14" align="center"/> **สถานะ:** สมบูรณ์ หลังจากดำเนินการ (แนวทางแก้ไข)

| แนวทางแก้ไข | ผลลัพธ์ | ผลกระทบ |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| **การดึงข้อมูล SNMP อย่างต่อเนื่อง** | รวบรวมข้อมูล telemetry โดยอัตโนมัติทุกๆ 30 วินาที | ขจัดการเดินตรวจเพื่อสุ่มเก็บข้อมูล |
| **การแจ้งเตือนทางสถิติ Z-Score** | ตรวจพบความผิดปกติที่ 3σ ก่อนที่เครื่องจักรจะล้มเหลว | การบำรุงรักษาเชิงรุก (Proactive) |
| **15 แดชบอร์ด** | โครงสร้างพื้นฐาน 5 รายการ (NOC, Engineering Drill-Down, Capacity, Meta-Monitoring, Ingestion Latency) + การผลิต 10 รายการ (Easy Overview, Alarm Console, Alarm Dictionary, Alarm Response (MTTA/MTTR), Engineering Analytics, Machine Snapshot, Manufacturing Command Center, Operator Andon, Data Readiness, Factory Digital Twin) | มองเห็นภาพรวมครบถ้วนทั้งโครงสร้างพื้นฐานและสายการผลิตจริง |
| **Webhooks ของ LINE/Teams** | ตรรกะการจัดรูปแบบการแจ้งเตือนและการพยายามส่งข้อมูลสมบูรณ์และถูกต้อง การจัดส่งจริงต้องใช้ข้อมูลรับรอง (Credentials) ที่กำหนดค่าโดยผู้ปฏิบัติงาน (`LINE_CHANNEL_ACCESS_TOKEN`, `TEAMS_WEBHOOK_URL`) ซึ่งไม่ได้รวมอยู่ในพื้นที่เก็บข้อมูลนี้ | ตอบสนองได้รวดเร็วขึ้นเมื่อมีการกำหนดค่า |
| **การวิเคราะห์เชิงทำนาย (Predictive)** | การพยากรณ์การถดถอยเชิงเส้น (Linear regression) | ป้องกันความล้มเหลว |

## 3. ตัวชี้วัด ROI

### เปรียบเทียบ ก่อน vs หลัง

| ตัวชี้วัด | ก่อนหน้า (ด้วยตนเอง) | หลังดำเนินการ (IMS) | การปรับปรุง |
| ----------------------- | -------------------------- | ----------------------------- | ------------------------------------------------ |
| **เวลาในการตรวจจับ** | 1-4 ชั่วโมง | **< 10 วินาที** | เร็วขึ้น 99.97% |
| **เวลาเฉลี่ยในการซ่อมแซม (MTTR)** | > 2 ชั่วโมง | **~15 นาที** | ลดลง 87.5% |
| **แรงงานคน** | 8 ชม./วัน (พนักงาน 2 คน) | **ยกเลิกการตรวจเช็คประจำวัน** | ประหยัดเวลา 2,920 ชม./ปี |
| **ความแม่นยำของข้อมูล** | ~85% (ข้อผิดพลาดจากมนุษย์) | **99.9%** | แม่นยำขึ้น +17.5% |
| **ความละเอียดของข้อมูล** | 6 ครั้ง/วัน | **2,880 ครั้ง/วัน** | ข้อมูลเพิ่มขึ้น 480 เท่า |
| **โหมดการบำรุงรักษา** | เชิงรับ (ซ่อมเมื่อพัง) | **เชิงทำนาย (ป้องกัน)** | การบำรุงรักษาเชิงรุกช่วยลด Downtime ได้อย่างชัดเจน |

### การประหยัดค่าใช้จ่ายรายปี

| หมวดหมู่ | ก่อนหน้า | หลังดำเนินการ | ประหยัด/ปี |
| ------------------------ | --------------------------------- | ------------------- | ----------------- |
| **ค่าลิขสิทธิ์** | 3,000,000-10,000,000 บาท | 0 บาท (โอเพ่นซอร์ส) | **3-10 ล้านบาท** |
| **แรงงานคน** | 730,000 บาท (2,920 ชม. × 250 บาท) | 0 บาท | **730,000 บาท** |
| **ต้นทุน Downtime** | 500,000 บาท/เหตุการณ์ × N | ใกล้ศูนย์ | **2-5 ล้านบาท** |
| **ประหยัดรวมต่อปี** | | | **5.7-15.7 ล้านบาท** |

### ระยะเวลาคืนทุน

```text
เงินลงทุนเริ่มต้น: ~200,000 บาท (ค่าแรงนักศึกษาฝึกงาน + ค่าคอมพิวเตอร์)
ประหยัดรายปี: ~5,700,000 บาท (แบบอนุรักษ์นิยม)
ระยะเวลาคืนทุน: < 1 เดือน
ROI: 2,750% (ปีที่ 1)
```

## 4. ความสำเร็จทางเทคนิค

| องค์ประกอบ | สิ่งที่ส่งมอบ |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Docker Stack** | 12 คอนเทนเนอร์ มีการจัดการดูแลอย่างสมบูรณ์ |
| **Telemetry Schema** | ไปป์ไลน์อิสระสองเส้นทาง — โครงสร้างพื้นฐาน (`sys_metrics`/`net_metrics`/`ldi_metrics`) และการผลิต LDI (`ldi_data`, 34 คอลัมน์: PE1-6, JE1-4, thickness, scan_speed, resist_dosage และอื่นๆ) — ดูเพิ่มเติม `docs/architecture/DATABASE_SCHEMA.md` |
| **กฎการแจ้งเตือน** | 30 กฎ: เฉพาะ LDI 6 ข้อ + โครงสร้างพื้นฐาน 11 ข้อ (ดั้งเดิมจาก Grafana), กฎการตรวจสอบแบบ Meta ไปป์ไลน์/แพลตฟอร์ม 13 ข้อ (Prometheus/Alertmanager) |
| **แดชบอร์ด** | 15 แดชบอร์ด (โครงสร้างพื้นฐาน 5 รายการ + การผลิต 10 รายการ) |
| **การทดสอบโหลด** | สูงสุด 1,000 VUs (`chaos-stress.js`, มีการจำลองข้อผิดพลาด 5%, เกณฑ์ความสำเร็จ >90%); `pipeline-stress.js` ตั้งเป้าความสำเร็จ >95% — ไม่ใช่การรับประกันความล้มเหลว 0% แต่เป็นงบประมาณความล้มเหลวที่ยอมรับได้ |
| **CI/CD** | GitHub Actions พร้อมการสแกนความปลอดภัย (Gitleaks) |
| **เอกสารประกอบ** | เอกสารกว่า 40+ ฉบับครอบคลุมด้านสถาปัตยกรรม การปฏิบัติงาน คู่มือผู้ใช้/ผู้ดูแลระบบ และคู่มือระดับองค์กร |

## 5. ผลลัพธ์การเรียนรู้จากการฝึกงาน

### ทักษะที่นักศึกษาฝึกงานได้รับ

| หมวดหมู่ | ทักษะ |
| ----------------- | ---------------------------------------------------------- |
| **สถาปัตยกรรม** | สถาปัตยกรรมแบบ 4 เลเยอร์ (4-Layer), ไมโครเซอร์วิส (Microservices), Docker |
| **เครือข่าย** | โปรโตคอล SNMP, MIB/OID, Counter Wrap Management |
| **ฐานข้อมูล** | TimescaleDB, PostgreSQL, Continuous Aggregates, PgBouncer |
| **การแสดงภาพ (Visualization)** | การออกแบบแดชบอร์ด Grafana, ระบบสีตามมาตรฐาน SRE |
| **การแจ้งเตือน** | Prometheus, Alertmanager, Z-Score, การวิเคราะห์เชิงทำนาย |
| **CI/CD** | GitHub Actions, การทดสอบอัตโนมัติ, การสแกนความปลอดภัย |
| **การทดสอบ** | การทดสอบโหลดด้วย K6, Chaos Engineering, Performance Tuning |
| **DevOps** | โครงสร้างพื้นฐานในรูปแบบโค้ด (IaC), Monitoring-as-Code, หลักการ SRE |

### คุณค่าของบุคลากรที่ผ่านการฝึกอบรม

> นักศึกษาฝึกงานได้เรียนรู้ **วงจรชีวิตการพัฒนาซอฟต์แวร์ที่สมบูรณ์** ตั้งแต่การออกแบบสถาปัตยกรรม → การพัฒนา → การทดสอบ → การนำไปใช้ (Deployment) → การตรวจสอบ (Monitoring)
