# 1. บันทึกการตัดสินใจเชิงสถาปัตยกรรม

วันที่: 2026-08-26

## สถานะ (Status)
ยอมรับ (Accepted)

## บริบท (Context)
เราจำเป็นต้องบันทึกการตัดสินใจทางสถาปัตยกรรมสำหรับโปรเจกต์นี้ หากไม่มีการบันทึกประวัติศาสตร์ สมาชิกใหม่ในทีมจะขาดความเข้าใจในบริบทว่าทำไมเทคโนโลยีบางอย่าง (เช่น Node-RED, TimescaleDB) จึงถูกเลือกใช้แทนทางเลือกอื่น

## การตัดสินใจ (Decision)
เราจะใช้ Architecture Decision Records (ADRs) เพื่อจัดทำเอกสารสำหรับทางเลือกเชิงสถาปัตยกรรมที่สำคัญ

## ผลที่ตามมา (Consequences)
เราจะจัดเก็บสิ่งเหล่านี้ไว้ใน `docs/architecture/decisions/`
