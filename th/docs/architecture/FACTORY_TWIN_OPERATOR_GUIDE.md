# Factory Twin — คู่มือผู้ปฏิบัติงาน

วิธีอ่านทวินชั้น 1 โดยไม่ตีความเกินกว่าข้อมูลที่มี

ใช้คู่กับ **[ระเบียบวิธีการสร้างใหม่](FACTORY_TWIN_RECONSTRUCTION.md)**,
**[สถาปัตยกรรมขณะรัน](FACTORY_TWIN_ARCHITECTURE.md)** และ
**[โมเดลความปลอดภัย](FACTORY_TWIN_SECURITY_MODEL.md)** (สามเอกสารนี้เป็นต้นฉบับภาษาอังกฤษ)

> [!IMPORTANT]
> สิ่งสำคัญที่สุดในหน้านี้: **สิ่งที่เห็นบนจอไม่ใช่ข้อเท็จจริงประเภทเดียวกันทั้งหมด** อาคาร เสา และผนังอ่านมาจาก
> CAD; ตำแหน่งและการหมุนของอุปกรณ์อ่านมาจาก CAD; *ขนาด* ของอุปกรณ์บางส่วนยังยืนยันไม่ได้;
> ไม่มีอุปกรณ์ที่ถูกเฝ้าระวังตัวใดถูกวาดบนผัง; และยังไม่มีสิ่งใดได้รับการยืนยันว่าเป็นเครื่องจริงเครื่องใด
> หน้าจอออกแบบมาเพื่อแยกสิ่งเหล่านี้ออกจากกัน การอ่านทั้งหมดรวมเป็นภาพเดียวคือความผิดพลาดที่ระบบนี้
> ถูกสร้างขึ้นมาเพื่อป้องกัน

## ความแตกต่างสี่ข้อ

สิ่งเหล่านี้ไม่ใช่การจับผิดตัวอักษร หากแยกไม่ออกแม้ข้อเดียว จะนำไปสู่การตัดสินใจที่ผิดอย่างเฉพาะเจาะจง

| ความแตกต่าง | หากแยกไม่ออกจะเกิดอะไรขึ้น |
|---|---|
| **สังเกตได้ ≠ ยืนยันแล้ว** | เสาหรือตำแหน่งที่ตรวจพบมีหลักฐานรองรับ แต่ **ไม่มีการระบุตัวตน** การถือว่าตำแหน่งที่สังเกตได้เป็นเครื่องที่รู้จักแล้ว จะทำให้นำสถานะสดไปผูกกับอุปกรณ์ที่ยังไม่มีใครระบุตัวตน |
| **จำลอง ≠ จริง** | *สถานะ* ของเครื่องคือ telemetry จริง *ตำแหน่ง* ของอุปกรณ์มาจาก CAD แต่ยังไม่มีอุปกรณ์ที่ถูกเฝ้าระวังตัวใดถูกวางหรือจับคู่กับตำแหน่งเหล่านั้น การเดินไปยังตำแหน่งบนจอโดยคาดว่าจะเจอเครื่องใดเครื่องหนึ่งจะพาไปผิดที่ |
| **คำนวณได้ ≠ วัดได้** | ความสูงระหว่างชั้นคำนวณจากระดับที่พิมพ์ไว้ในแบบ ส่วนความสูงใต้พื้นชั้นบนยังไม่ทราบเลย การใช้ตัวเลขที่คำนวณมาเป็นระยะความสูงปลอดภัยคือความผิดพลาดด้านความปลอดภัยทางกายภาพ |
| **ไม่ทราบ ≠ ขาดหาย** | ความสูงที่ว่าง ตำแหน่งที่ยังไม่จับคู่ หรือผนังที่ไม่มี หมายถึง *ไม่มีแหล่งข้อมูล* ไม่ใช่มีคนลืมใส่ ไม่มีสิ่งใดรอดำเนินการอยู่ มีเพียงสิ่งที่ไม่มีอยู่ |

## หน้าจอ

ส่วนประกอบของหน้าจอ **ต่อกันเป็นแถบ** ส่วนหัว แถบสถานะ ผังพื้น และลิ้นชักตรวจสอบเป็นช่องของเลย์เอาต์
ไม่ใช่หน้าต่างลอย จึงไม่มีสิ่งใดถูกวาดทับผังพื้น การเปิดลิ้นชักทำให้ผังแคบลง แต่ไม่ปิดทับผัง

```
HEADER          factory identity · view controls · data quality · build id · Inspection
STATUS STRIP    Off  Down  Idle  Initial  PM  Stop  Run  Undefined  |  Unmapped
FLOOR                                                        INSPECTION DRAWER
                the plan or the model, full width              factory KPIs
                                                               layers
                CONTEXT PANEL appears here, bottom-left,       machine states
                only after you select something                evidence
                                                               devices
                                                               diagnostics
```

**แผงบริบท (context panel)** เป็นองค์ประกอบเดียวที่อนุญาตให้อยู่เหนือผังพื้น แสดงเฉพาะเมื่อมีการเลือก
มีขนาดจำกัดและเลื่อนดูได้ ชุด regression จะทดสอบการคลิกที่กึ่งกลาง canvas ใน 5 viewport — 1366×768, 1920×1080,
2560×1440, 3840×2160 และ 600×1000 แนวตั้ง — และจะล้มเหลวหากมีสิ่งอื่นนอกจาก canvas อยู่ตรงนั้น

เมื่อความกว้างต่ำกว่า 900 px ลิ้นชักจะซ้อนทับแทนการต่อเป็นแถบ เพราะแถบกว้าง 340 px บนจอ 600 px
จะทำให้อ่านผังไม่ได้ กฎที่คงอยู่ทุกความกว้างคือ **ช่องผังพื้นไม่เคยขยายเพื่อหลบ** และปิดลิ้นชักได้เสมอ

**มีตัวระบุ build บนหน้าจอ** ชิป `build …` ในส่วนหัวคือลายนิ้วมือของ build ที่กำลังทำงาน ดึงจาก
`/api/build` และคำนวณตอนเริ่มระบบจากไบต์ของไฟล์ต้นฉบับที่อยู่ใน image ที่รันจริง ไม่ใช่ค่าคงที่ที่เขียนไว้ในหน้า
— ค่าคงที่จะแสดงค่าเดิมตั้งแต่ครั้งล่าสุดที่มีคนแก้ ซึ่งเป็นเหตุให้การ deploy ที่ล้าสมัยมองไม่เห็น
หาก 2 service แสดงลายนิ้วมือเดียวกัน แปลว่ารันโค้ดชุดเดียวกัน

## มุมมอง

มีมุมกล้องตั้งไว้ 3 แบบ **เริ่มที่ 2D ก่อน** เพราะเป้าหมายของทวินขณะนี้คือความถูกต้องทางกายภาพ ผังจึงเป็นมุมมองหลัก
**การเปลี่ยนมุมมองเปลี่ยนเฉพาะกล้อง** — ไม่มีมุมมองใดย้ายวัตถุ เปลี่ยนพิกัด หรือเปลี่ยนสถานะหลักฐาน
และ regression ยืนยันว่าสตริงพิกัดที่เรนเดอร์เหมือนกันทุกไบต์ทั้งก่อนและหลังการสลับทุกครั้ง

| มุมมอง | การจัดกรอบ | ใช้เมื่อ |
|---|---|---|
| **2D Plan** | **ค่าเริ่มต้น** มองตรงลงมา: ผังพื้นจาก CAD — เส้นรอบนอก ผนังตามความหนาที่วัดได้ เสา ช่องเปิด พื้นที่ และอุปกรณ์ | ตรวจทวินเทียบกับแบบ อ่านผังพื้นเหมือนอ่านแบบ |
| **3D** | มุมเฉียง จัดให้พอดีทั้งชั้น | พาผู้บริหาร/NOC ชมภาพรวม ทำความเข้าใจอาคารในรูปปริมาตร |
| **Fit floor** | จัดกรอบให้พอดีขอบเขตอาคารที่วัดได้ โครงสร้างทั้งหมดอยู่ในกรอบ | กลับสู่มุมที่รู้จักหลังหมุนกล้อง |

ทั้งสามคือฉากเดียวกันและพิกัดเดียวกันที่มองจากคนละมุม — ไม่ใช่แบบคนละชุด ผังและโมเดล 3 มิติจึงไม่มีทาง
ขัดแย้งกันเรื่องตำแหน่งผนัง

กล้อง **Operator** ที่ปรับด้วยมือถูกเอาออกแล้ว เพราะมันจัดกรอบกริดอุปกรณ์สังเคราะห์ที่ไม่มีอยู่แล้ว จึงเหลือแต่พื้นว่าง

**มุมมองจะถูกปิดใช้งานจนกว่าข้อมูลที่กำหนดมุมมองนั้นจะมาถึง** ปุ่มที่ใช้ไม่ได้แปลว่ายังไม่ได้โหลดขอบเขตอาคารที่วัดได้
— สาเหตุที่พบบ่อยคือการ clone ใหม่ซึ่งไม่มี geometry ที่เป็นข้อมูลลับ

**Reset camera** จัดกรอบตามมุมมองที่ใช้อยู่ใหม่ แต่ไม่สลับมุมมอง: การเลือกมุมมองเป็นสิทธิ์ของคุณ
ส่วนตำแหน่งที่กล้องค้างอยู่หลังหมุนไม่ใช่

## เลเยอร์

หนึ่งสวิตช์ต่อหนึ่งประเภทหลักฐาน ไม่ใช่ตามความสะดวกของการจัดกลุ่ม การซ่อนเลเยอร์ซ่อนเฉพาะ mesh
ไม่ลบวัตถุ ไม่เปลี่ยนจำนวน และไม่เปลี่ยนผลลัพธ์ของ API

| เลเยอร์ | ประกอบด้วย | ประเภทหลักฐาน |
|---|---|---|
| **Floor shell** | แผ่นพื้น เส้นขอบเขตอาคารที่วัดได้ และเส้นกริดที่สำรวจแล้ว | ขอบเขตแบบ MEASURED |
| **Columns** | เสาโครงสร้างที่อ่านจาก CAD | MEASURED_CAD |
| **Walls and openings** | ผนังภายในและผนังกั้น รวมทั้งประตู หน้าต่าง และห้อง air shower | MEASURED_CAD สำหรับผังและความหนา; **ความสูงเป็น PRESENTATION_ONLY** |
| **Functional zones** | เฉพาะพื้นที่กระบวนการ/พื้นที่ใช้งานที่ผ่านการตรวจสอบ | OBSERVED_CAD (เฉพาะระดับที่ผ่านการตรวจสอบ) |
| **Equipment** | block reference ของ CAD: 344 ตำแหน่ง มีขนาดที่วัดได้ 270 ตำแหน่ง และ 213 ตำแหน่งในนั้นวาดเป็นเส้นรอบรูปตามที่ CAD วาด แทนกล่องสี่เหลี่ยม | MEASURED_CAD สำหรับตำแหน่ง การหมุน และขนาด; UNRESOLVED สำหรับขนาดของ 74 ตำแหน่ง วาดเป็นเครื่องหมายขนาดเท่ากันทั้งหมด |
| **Raw CAD reference** | เส้นของแบบต้นฉบับ วาดทับการสร้างใหม่ | ไม่ใช่เลเยอร์ของผังพื้น — เป็น **ต้นทาง** ที่ใช้ตรวจผังพื้น |

เลเยอร์อ้างอิงถูกคั่นจากเลเยอร์ด้านบนด้วยเส้นแบ่ง เพราะเป็นสิ่งคนละประเภท เลเยอร์อื่นทั้งหมดคือโมเดล:
geometry ที่ผ่านการจับคู่ รวม และจัดประเภทแล้ว ส่วนเลเยอร์อ้างอิงคือแบบต้นฉบับที่ไม่ผ่านขั้นตอนเหล่านั้นเลย
วาดเป็นเส้นบางสีอำพันทับโมเดลเพื่อให้เทียบด้วยตาได้ หากไม่ตรงกัน แบบต้นฉบับคือสิ่งที่ถูก

เลเยอร์นี้ปิดไว้โดยค่าเริ่มต้นและจะดึงข้อมูลครั้งแรกเมื่อเปิดใช้ มุมมองผังพื้นปกติจึงไม่ต้องเสียทรัพยากรกับมัน
และแสดงให้เห็นสิ่งที่ตัดออก: **block reference** ของประตู หน้าต่าง และ air shower 393 รายการ **ไม่ถูกขยาย**
คุณจะเห็นช่องเปิดในผนังแต่ไม่เห็นบานประตู และแบบรายละเอียดของอุปกรณ์ที่อยู่ใน modelspace เดียวกันถูกตัดออกทั้งหมด

แต่ละสวิตช์แสดงจำนวนสด — เช่น สวิตช์โซนแสดงจำนวนที่ผ่านการตรวจสอบเทียบกับที่ถูกระงับ และสวิตช์อุปกรณ์แสดง
จำนวนขนาดที่เป็น UNRESOLVED **โซนที่ถูกระงับจะไม่ถูกเรนเดอร์ไม่ว่าตั้งสวิตช์อย่างไร** เพราะไม่ผ่านการตรวจสอบ
หรือเกี่ยวข้องกับข้อขัดแย้งที่ยังไม่ได้แก้ และสวิตช์ไม่มีสิทธิ์ยกระดับโซนเหล่านั้น

## การอ่านอุปกรณ์

ทุก asset บนผังพื้นมาจาก block reference ของ CAD และแต่ละรายการมี **ข้อกล่าวอ้างสองข้อที่น้ำหนักต่างกัน**:

| | ข้อกล่าวอ้าง | วาดเป็น |
|---|---|---|
| **ตำแหน่งและการหมุน** | `MEASURED_CAD` — ระบุโดยระเบียน `INSERT` ของแบบเอง ไม่มีการลากเส้น snap เฉลี่ย หรือ fit ใด ๆ | อยู่ตรงไหนและวางอย่างไร |
| **ขนาด** | `MEASURED_CAD` สำหรับ 270 จาก 344 asset (วัดจาก geometry ของ block เองหลังแปลงพิกัด); `UNRESOLVED` สำหรับ 74 รายการ | แผ่นทึบสีอ่อนกว่า (213 รายการวาดเป็นเส้นรอบรูปตามที่ CAD วาด) — หรือเครื่องหมายเล็กขนาดเท่ากัน |

**เครื่องหมายขนาดเท่ากันหมายความว่า CAD ไม่ได้ระบุขนาดของเครื่องนั้น** block มีขนาดเล็กกว่าระดับเครื่องจักร
หรือวาดเป็นพื้นที่แทนที่จะเป็น asset เดียว จึงอ่าน geometry เป็นตัวเครื่องไม่ได้ ไม่มีการใช้กล่องค่าเริ่มต้นแทน
เครื่องหมาย unresolved ทุกอันมีขนาดเท่ากันโดยตั้งใจ: ต้องไม่มีทางถูกเข้าใจผิดว่าเป็นค่าที่วัดได้

**ไม่ทราบความสูงของ asset ใดเลย** ผังพื้นไม่มีข้อมูลระดับความสูงของอุปกรณ์ ทุกอย่างจึงเป็นแผ่นแบน
ไม่เคยเป็นรูปทรงปริมาตรที่สื่อถึงความสูงที่ไม่มีใครอ่านได้

## สิ่งที่ไม่ถูกวาดแล้ว

มีสามสิ่งที่ถูกเอาออก และแต่ละอย่างถูกเอาออกที่เส้นทางข้อมูล ไม่ใช่แค่ซ่อนไว้:

- **อุปกรณ์ที่ถูกเฝ้าระวังทุกตัว** เดิมทวินวาดทั้ง 23 ตัวบนกริดสังเคราะห์ ปัจจุบัน route การคำนวณ mesh
  และแผ่นพื้นที่กำหนดขนาดจากกริดนั้นถูกลบทั้งหมด บนผังที่อ่านจาก CAD ตำแหน่งที่แต่งขึ้นซึ่งอยู่ข้างตำแหน่งที่วัดได้
  จะแยกด้วยตาไม่ออก telemetry ยังเป็นของจริงและยัง poll ทุก 5 วินาที ใช้ขับแถบสถานะและรายการอุปกรณ์
  แต่ไม่ได้ใส่สีให้สิ่งใดบนผัง
- **ตำแหน่งอุปกรณ์จากภาพสแกน 243 ตำแหน่ง** แปลงจากภาพสแกนของแบบที่พิมพ์ออกมา ตำแหน่งซ้าย/ขวา ขนาด
  และทิศทางล้วนมาจากภาพสแกน ไม่ใช่จากแบบ ปัจจุบันเก็บไว้ในเอกสารส่วนที่เป็นข้อมูลลับเป็นบันทึกที่ถูกแทนที่แล้ว
  และไม่ให้บริการที่ใดเลย
- **รูปทรงเครื่องจักรที่แต่งขึ้น** ตัวเครื่องที่เลือกจากตารางรูปทรงซึ่งไม่มีใครวัด วาดทับตำแหน่งจากภาพสแกนเหล่านั้น
  — เป็นข้อกล่าวอ้างที่ไม่ได้วัดสองชั้นซ้อนกัน และแสดงด้วยน้ำหนักภาพเท่ากับข้อมูล CAD ข้าง ๆ

ไม่มีสิ่งใดในฉากเปิดการเจาะลึกรายเครื่อง เพราะไม่มีสิ่งใดในฉาก *เป็น* เครื่องจักร การเจาะลึกจะต้องเริ่มจากตำแหน่ง
และไม่มีตำแหน่งใดบนชั้นนี้ผูกกับอุปกรณ์ด้วยบันทึกที่เชื่อถือได้

**มุมมองแผนผังจากภาพสแกน** ก็ถูกเอาออกจากหน้านี้แล้ว ตัวข้อมูลที่ถอดแบบไว้ยังมีอยู่และ `/api/floor-schematic`
ยังให้บริการ แต่ Factory Twin หลักคือผังพื้นจาก CAD และการผสมแบบที่ไม่ได้ตามมาตราส่วนเข้ามาในหน้าเดียวกัน
คือสาเหตุที่ geometry จากภาพสแกนเคยหลุดเข้ามาในมุมมองทางกายภาพ

## แถบสถานะ — มี 8 สถานะพอดี

คำเหล่านี้เป็นคำของโรงงานเอง ไม่ใช่ศัพท์เฝ้าระวังที่มุมมองนี้คิดขึ้น ผู้ปฏิบัติงานที่อ่านบอร์ดนี้กับผู้ที่อ่าน HMI
ของไลน์จะเห็นคำเดียวกันสำหรับเครื่องเดียวกัน

| สถานะ | ความหมาย |
|---|---|
| **Off** | *ไม่มีแหล่งข้อมูล* ปิดเครื่องอยู่ ไม่มีคอลัมน์ใดใน schema นี้รายงานค่านี้ |
| **Down** | มี alarm ระดับ Critical หรือ Major ที่ active อยู่บน asset ที่จับคู่แล้ว |
| **Idle** | asset ที่จับคู่แล้วมีอยู่และรายงานข้อมูล แต่ไม่ได้ทำงาน |
| **Initial** | *ไม่มีแหล่งข้อมูล* กำลังอุ่นเครื่องหรือเริ่มงาน |
| **PM** | *ไม่มีแหล่งข้อมูล* บำรุงรักษาตามแผน |
| **Stop** | *ไม่มีแหล่งข้อมูล* ถูกหยุดโดยตั้งใจ |
| **Run** | asset ที่จับคู่แล้วกำลังทำงานโดยไม่มี alarm ที่ active |
| **Undefined** | asset ที่จับคู่แล้วแต่หลักฐานไม่พอจะระบุสถานะ |

มี 4 สถานะที่ระบุว่า **NO SOURCE** และแสดงเป็น **ขีด ไม่ใช่ศูนย์** นี่คือข้อความเกี่ยวกับ *ระบบ* ไม่ใช่เกี่ยวกับหน้างาน:
การติดตั้งนี้ไม่มีคอลัมน์ที่จะจุดไฟสถานะเหล่านั้นได้ ศูนย์คือค่าที่วัดได้ ("ไม่มีเครื่องใดอยู่ใน PM")
ส่วนขีดคือความจริง ("ระบบนี้บอกคุณไม่ได้")

**Unmapped ไม่ใช่สถานะที่เก้า** อยู่หลังเส้นคั่นเพราะเป็นข้อเท็จจริงเกี่ยวกับ *ระเบียน* — asset ไม่มีการเชื่อมโยง
ที่เชื่อถือได้กับอุปกรณ์ใด — ไม่ใช่เกี่ยวกับเครื่องจักร asset ที่ยังไม่จับคู่ไม่ใช่ Off และไม่ใช่ Undefined ด้วย
ไม่มีสถานะเครื่องจักรใดใช้กับมันได้เลย

กฎสองข้อที่เป็นจริงเสมอไม่ว่าบนจอแสดงอะไร:

- **เครื่องที่ระบุสถานะไม่ได้จะแสดงเป็น Undefined** ไม่ใช่ Idle, Off หรือ Run ที่ดูน่าเชื่อ การค้นหาที่ล้มเหลว
  ต้องไม่ถูกอ่านเป็นเครื่องที่ปกติ และต้องไม่ถูกอ่านเป็นเครื่องที่ปิดอยู่ด้วย
- **สถานะต้องอาศัยการจับคู่อุปกรณ์ที่เชื่อถือได้** ตำแหน่ง ลำดับเลข และความคล้ายของชื่อไม่เคยสร้างการจับคู่ได้
  เมื่อ **ปัจจุบันมีการจับคู่ที่ยืนยันแล้ว 0 รายการ asset ทางกายภาพทุกตัวบนชั้นนี้จึงเป็น Unmapped**
  และไม่มีสถานะสดถูกวาดบน asset ใดเลย

ทุกแถวมีสัญลักษณ์เฉพาะนอกเหนือจากสี คำศัพท์จึงยังอ่านได้บนจอขาวดำ บนโปรเจกเตอร์ และสำหรับผู้ที่บกพร่องการมองเห็นสี

สถานะที่ถูกเอาออก — NORMAL, WARNING, CRITICAL, OFFLINE, STALE DATA, MAINTENANCE, PRESENTATION ONLY —
เป็นสิ่งที่มุมมองนี้คิดขึ้นเอง regression จะล้มเหลวหากมีสถานะใดในนี้กลับมาบนบอร์ด

## คำอธิบายหลักฐาน (Evidence legend)

เปิด **Evidence legend** ในแผง ทุกสถานะแสดงเป็น **สัญลักษณ์ + คำ** โดยสีทำหน้าที่เสริมเท่านั้น:

| สัญลักษณ์ | สถานะ | ความหมาย |
|---|---|---|
| ▣ | **MEASURED** | อ่านจากแหล่งข้อมูลและตรวจสอบไขว้แล้ว |
| ▲ | **DERIVED** | คำนวณจากข้อมูลที่วัดได้ ไม่ได้อ่านโดยตรง |
| ◆ | **OBSERVED** | ตรวจพบและยืนยันด้วยตา; **ไม่มีการกล่าวอ้างตัวตน** |
| ◇ | **SIMULATED** | ตั้งใจให้ไม่ใช่ของจริง |
| ? | **UNKNOWN** | ไม่มีแหล่งข้อมูล ไม่ได้รอดำเนินการ |
| ✓ | **CONFIRMED** | เชื่อถือได้อย่างเป็นทางการ **ไม่มีสิ่งใดใน build นี้เป็น CONFIRMED** |

สีไม่เคยเป็นช่องทางเดียว บนจอขาวดำหรือสำหรับผู้บกพร่องการมองเห็นสีใด ๆ สัญลักษณ์และคำยังสื่อสถานะได้ครบ

## ตัวตรวจสอบ (Inspector)

เมื่อชี้เมาส์ที่วัตถุ ตัวตรวจสอบจะเปิดขึ้น และรายงานเฉพาะ metadata ภาพรวมที่ปลอดภัย: **ประเภทวัตถุ สถานะหลักฐาน
ประเภทที่มา ความเชื่อมั่น สถานะการจับคู่ และสถานะความสูง**

ตัวตรวจสอบตั้งใจไม่แสดงชื่อไฟล์ path ในระบบไฟล์ เนื้อหาเอกสารต้นทาง ชื่อผู้ผลิต ชื่อกระบวนการ หรือ credential
หากต้องการค่าที่ไม่มีแสดง แปลว่าถูกระงับโดยการออกแบบ — ดู **[โมเดลความปลอดภัย](FACTORY_TWIN_SECURITY_MODEL.md)**

สิ่งที่คุณจะเห็นและความหมาย:

| ฟิลด์แสดงว่า | ความหมาย |
|---|---|
| `UNMAPPED` | ไม่มีบันทึกที่เชื่อถือได้ผูกตำแหน่งนี้กับอุปกรณ์ใด เป็นสถานะของ asset **ทุกตัว** ในปัจจุบัน |
| Footprint `UNRESOLVED — no size is claimed` | CAD ไม่ได้ระบุขนาดของ asset นี้ ไม่มีการกล่าวอ้างขนาดและวาดเพียงเครื่องหมายขนาดเท่ากัน |
| Position evidence `MEASURED_CAD` | อ่านตรงจาก `INSERT` ของ CAD: จุดวางและการหมุนเป็นของแบบเอง |
| Footprint evidence `MEASURED_CAD — the block's own geometry, transformed and measured` | ขนาดวัดจาก geometry ของ block เองผ่านห่วงโซ่ `INSERT` ทั้งหมด |
| Footprint evidence `UNRESOLVED — not established by the CAD` | ไม่มีหลักฐานขนาดสำหรับ asset นี้ |
| height `unknown — not in evidence` | ผังพื้นไม่มีข้อมูลระดับความสูงของอุปกรณ์ ไม่มีการประมาณค่าใด ๆ |

ตัวตรวจสอบแสดงตำแหน่งและขนาดเป็น **สองแถวแยกกันพร้อมระดับหลักฐานแยกกัน** เพราะเป็นข้อกล่าวอ้างสองข้อ
ที่น้ำหนักต่างกันบนระเบียนเดียวกัน การอ่านรวมเป็นข้อเดียวคือความผิดพลาดที่เลย์เอาต์นี้ป้องกัน

## การเข้าถึง (Accessibility)

- **คีย์บอร์ด:** ปุ่มมุมมอง ปุ่ม reset สวิตช์ Inspection ช่องเลือกเลเยอร์ทุกช่อง และส่วนขยายทุกส่วนเป็น control มาตรฐาน
  ที่เข้าถึงได้ด้วย <kbd>Tab</kbd> และใช้ <kbd>Space</kbd> / <kbd>Enter</kbd> เพื่อสั่งงาน การหมุนกล้องเป็นการโต้ตอบด้วย pointer
  แต่มุมมองตั้งไว้ทั้งสามแบบและปุ่ม reset ให้ผู้ใช้คีย์บอร์ดอย่างเดียวได้มุมกล้องครบโดยไม่ต้องหมุน
- **โฟกัสที่มองเห็นได้:** เส้นโฟกัสแสดงชัดเจน ไม่ได้ถูกซ่อนตามค่าเริ่มต้น
- **คอนทราสต์:** ข้อความในส่วนหัว แถบสถานะ และลิ้นชักมีอัตราคอนทราสต์ 4.5:1 เทียบกับพื้นหลังของแผงในขนาดที่ใช้
- **ไม่ใช้สีอย่างเดียว:** ทุกสถานะหลักฐานมีสัญลักษณ์และคำ
- **Live regions:** ตัวตรวจสอบประกาศแบบสุภาพ ไม่ขัดจังหวะ

ยืนยันแล้วที่ 1366×768, 1920×1080, 2560×1440, 3840×2160 และ viewport แนวตั้ง 600×1000 ดู **[Visual QA](FACTORY_TWIN_VISUAL_QA.md)**
