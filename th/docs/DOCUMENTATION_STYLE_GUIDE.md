# มาตรฐานการเขียนเอกสาร (Style Guide)

เอกสารทั้งหมดของ IMS ต้องปฏิบัติตามมาตรฐาน Hyper-scaler ดังนี้:

## 1. กฎ "Auto-Clarity"
ตัดคำเยิ่นเย้อทิ้งทั้งหมด (เช่น "เพียงแค่", "จริงๆ แล้ว", "โดยพื้นฐาน") ให้เข้าถึงแก่นทางเทคนิคทันที

## 2. ใช้ Active Voice (ประโยคเน้นประธาน)
- **ไม่ดี**: Dashboard ถูกรีโหลดโดยสคริปต์
- **ดี**: สคริปต์รีโหลด Dashboard

## 3. การใช้ GitHub Alerts
เน้นข้อมูลสำคัญให้เห็นชัดเจน:
- `> [!NOTE]` สำหรับข้อมูลบริบท
- `> [!WARNING]` สำหรับการกระทำที่อาจเกิดความเสียหาย
- `> [!IMPORTANT]` สำหรับข้อกำหนดที่สำคัญที่สุด

## 4. ระดับของหัวข้อ (Header Nesting)
ห้ามซ้อนหัวข้อลึกเกิน H3 (`###`) หากต้องการโครงสร้างที่ลึกกว่านี้ ให้ใช้ตัวหนาหรือ Bullet List แทน
