# การทบทวนความสมบูรณ์ของ SOP (SOP Completion Review)

> การทบทวนเฉพาะเอกสารเท่านั้น, 2026-08-14, เป็นส่วนหนึ่งของเส้นทาง
> การรวบรวมหลักฐาน (Evidence Consolidation) ไม่มีการแตะต้องระบบรันไทม์
> ขอบเขต: `docs/operations/SOP_OPERATOR*.md`
> และ `docs/operations/ALARM_PLAYBOOK.md` เทียบกับแดชบอร์ดจริงที่ใช้งาน
> และแคตตาล็อกหลักของสัญญาณเตือน (alarm master catalog)

## สิ่งที่ได้รับการแก้ไขในรอบนี้: ลิงก์แดชบอร์ดที่เสีย 2 รายการ ในทั้ง 3 ภาษา

`SOP_OPERATOR.md`, `SOP_OPERATOR-th.md`, `SOP_OPERATOR-zh-CN.md` แต่ละไฟล์
มีลิงก์ไปยัง URL แดชบอร์ดสองรายการที่ไม่ตรงกับ `uid` ของแดชบอร์ดจริง
(ตรวจสอบกับไฟล์ `.json` จริง ไม่ได้คาดเดาเอาเอง):

| ข้อความลิงก์           | URL ที่เสียซึ่งถูกใช้งาน | uid ที่แท้จริง    |
| ---------------------- | ------------------------ | ----------------- |
| Engineering Drill-Down | `/d/ims-engineering`     | `ims-engineering` |
| Capacity Planning      | `/d/ims-capacity`        | `ims-capacity`    |

ทั้งสองรายการผิดพลาดเหมือนกันในเอกสารทั้งสามภาษา -- ข้อผิดพลาดเดียวกัน
ที่กระจายไปจากการแปล ไม่ใช่ข้อผิดพลาดอิสระสามรายการ
แก้ไขแล้วในรอบนี้ (แก้ลิงก์ทั้งหมด 6 รายการ, 2 รายการต่อไฟล์) สำหรับลิงก์แดชบอร์ด
อื่นๆ ใน `SOP_OPERATOR.md` (NOC Overview, LDI Manufacturing,
Operator Andon โดยนัย, Machine Snapshot, Meta-Monitoring) ได้รับการ
ตรวจสอบกับ `uid` จริงแล้วและมีความถูกต้อง

## ช่องโหว่จริงที่ยังไม่ได้แก้ไข: ฟิลด์ `sop_reference` มีการเติมข้อมูล 0%

`public.ldi_alarm_ms_code.sop_reference` (เพิ่มเข้ามาตามประวัติของ
repo นี้เอง, งาน "structured Cause/Impact/Recovery fields, SOP reference
field") มีอยู่เป็นคอลัมน์ แต่มี **ค่าที่ไม่ว่างเปล่าเป็นศูนย์จากทั้งหมด
1,820 แถว** -- ตรวจสอบบนระบบที่ใช้งานจริง:

```sql
SELECT count(*) FILTER (WHERE sop_reference IS NOT NULL AND sop_reference <> '')
FROM public.ldi_alarm_ms_code;
-- Result: 0
```

เพื่อเปรียบเทียบ ฟิลด์ `cause`/`impact`/`recovery_action` ในแคตตาล็อกเดียวกัน
มีการเติมข้อมูลใน 25 จาก 1,820 แถว -- และทั้ง 25 แถวนั้นคือรหัสที่
ตัวจำลอง (simulator) สามารถส่งได้พอดี บวกกับรหัส Critical เพิ่มเติม
อีกเล็กน้อยที่คัดเลือกด้วยมือ (ตรวจสอบแล้ว: ID ทั้ง 25 รายการตรงกับ
รายการรหัสที่ใช้งานอยู่ของตัวจำลองจาก `alarm-sync-linter.js` เกือบทั้งหมด)
ดังนั้นฟิลด์ _คำแนะนำที่มีโครงสร้าง (structured guidance)_ จึงได้รับความสนใจ
ตามขอบเขตอย่างแท้จริง ส่วนฟิลด์ _การเชื่อมโยง SOP (SOP-linkage)_
กลับไม่ได้รับการสนใจใดๆ

นี่ไม่ใช่ช่องโหว่เดียวกับ "ALARM_PLAYBOOK.md ไม่สมบูรณ์" --
`ALARM_PLAYBOOK.md` ครอบคลุมรหัสที่ใช้งานจริงของตัวจำลองทั้ง 19-21 รายการ
ด้วยข้อความสำหรับการตอบสนองเบื้องต้นจริง ตรวจสอบเทียบกับฐานข้อมูล
และไฟล์กฎการแจ้งเตือน (alert rule files) บนระบบจริงแล้ว (ยืนยันโดยการอ่าน
ในรอบนี้ เนื้อหามีความแม่นยำและเป็นปัจจุบัน) ช่องโหว่นั้นแคบกว่า: ไม่มีอะไรใน
`ldi_alarm_ms_code.sop_reference` ที่ชี้ _กลับ_ ไปยังคู่มือนั้น (หรือ
ไปยังเอกสาร SOP อื่นใด) ในแต่ละรหัส ดังนั้นการคิวรี (query) แคตตาล็อกหลัก
เพียงอย่างเดียว จึงไม่สามารถตอบได้ว่า "SOP ใดครอบคลุมสัญญาณเตือนนี้"

## คำแนะนำ (ยังไม่ได้ดำเนินการ นี่คือการทบทวน ไม่ใช่การแก้ไข)

สำหรับรหัสที่เกี่ยวข้องกับการดำเนินงานประมาณ 19-25 รายการเดิมที่มีการ
เติมข้อมูลใน `cause`/`impact`/`recovery_action` แล้ว ควรเพิ่มค่า
`sop_reference` ที่ชี้ไปยัง anchor ของส่วนที่เกี่ยวข้องใน `ALARM_PLAYBOOK.md`
(เช่น `ALARM_PLAYBOOK.md#1-ldi-machine-alarm-codes`) หรือ anchor
สำหรับแต่ละรหัสในอนาคต หากคู่มือมีการปรับโครงสร้างใหม่ นี่เป็นการย้ายข้อมูล
(migration) เชิงกลไกขนาดเล็ก (`UPDATE ldi_alarm_ms_code SET sop_reference =
... WHERE alarm_id IN (...)`) ซึ่งมีความเสี่ยงต่ำในลักษณะเดียวกับการเติมข้อมูล
`cause`/`impact`/`recovery_action` ที่เกิดขึ้นแล้ว --
ไม่ได้กำหนดขอบเขตหรือดำเนินการที่นี่ เนื่องจากเป็นการเขียนฐานข้อมูล และ
การทบทวนนี้จงใจให้เป็นแบบอ่านอย่างเดียว (read-only) ในช่วงของการระงับ (freeze)

## สิ่งที่ไม่ได้ทบทวนในรอบนี้

- ความถูกต้องของเนื้อหาใน `ALARM_PLAYBOOK.md` ที่นอกเหนือไปจากการอ่านผ่านๆ --
  ได้สุ่มตรวจสอบเทียบกับรายการรหัสของตัวจำลองที่ทำงานอยู่และพบว่า
  มีความสอดคล้องกัน แต่ไม่ได้ตรวจสอบทบทวนทีละบรรทัดกับไฟล์ YAML
  กฎการแจ้งเตือนปัจจุบัน ตามที่ระบุไว้ในส่วนหัวของเอกสารตอนต้น (2026-08-10)
- `docs/product/ONBOARDING_SCRIPT.md` (ตรงกับ grep ของ SOP ด้วย) --
  อยู่นอกเหนือขอบเขต นั่นคือเอกสารปฐมนิเทศ (onboarding) ไม่ใช่ SOP ของผู้ปฏิบัติงาน
