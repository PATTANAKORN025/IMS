# การเริ่มต้นใช้งาน IMS: สคริปต์วิดีโอแนะนำและการสร้าง GIF

> **วัตถุประสงค์:** เอกสารนี้ทำหน้าที่เป็นสตอรี่บอร์ดและสคริปต์สำหรับการสร้างวิดีโอแนะนำและ GIF สำหรับ UI ของระบบ IMS อย่างเป็นทางการ เนื่องจาก UI เป็นรูปแบบ Cyberpunk HUD การเคลื่อนไหวและแอนิเมชันจึงเป็นจุดขายหลัก

---

## คำแนะนำเกี่ยวกับเครื่องมือ

สำหรับการบันทึกเนื้อหาการเริ่มต้นใช้งาน โปรดใช้เครื่องมือต่อไปนี้:

1. **การบันทึกหน้าจอ (วิดีโอ):** OBS Studio (1080p, 60fps) เพื่อให้ได้แอนิเมชัน Grafana ที่ลื่นไหล
2. **การบันทึก GIF:** [Kap](https://getkap.co/) (macOS) หรือ ScreenToGif (Windows) ส่งออกที่ 24fps เพื่อให้การเปลี่ยนหน้าจอ UI เป็นไปอย่างราบรื่น
3. **สถานะเบราว์เซอร์:** รัน Chrome ในโหมด Kiosk `http://localhost:3000/d/ims-noc-overview?kiosk=tv` เพื่อซ่อนแถบ URL และแถบเมนูของระบบปฏิบัติการ (OS chrome)

---

## ฉากที่ 1: ภาพรวม NOC (สร้างความตื่นตาตื่นใจ "Wow" Factor)

**ประเภทเนื้อหา:** วิดีโอวนซ้ำ (GIF) ความยาว 15 วินาที (`hero-noc.gif`)
**ตำแหน่งที่ตั้งเป้าหมาย:** ด้านบนของ `README.md` (แทนที่แบนเนอร์แบบคงที่หากต้องการ)

**สคริปต์การดำเนินการ:**

1. เปิด [ภาพรวม NOC](http://localhost:3000/d/ims-noc-overview)
2. ตั้งค่าการรีเฟรชอัตโนมัติของ Grafana เป็น `5s` เพื่อให้กราฟเคลื่อนไหวตลอดเวลาระหว่างการบันทึก
3. เลื่อนเมาส์อย่างนุ่มนวลไปที่เกจวัด **คะแนนความสมบูรณ์ของระบบ (Fleet Health Score)** เพื่อแสดง Tooltip
4. เลื่อนเมาส์ลงไปยังรายการ **10 โหนดวิกฤตอันดับแรก (Top 10 Critical Nodes)** ในขณะที่มีการจัดเรียงข้อมูลใหม่แบบไดนามิก
5. หยุดการบันทึก

---

## ฉากที่ 2: ขั้นตอนการเจาะลึกข้อมูล (การแก้ไขปัญหา)

**ประเภทเนื้อหา:** วิดีโอความยาว 45 วินาทีพร้อมเสียงบรรยาย / ข้อความบนหน้าจอ (`drilldown-tutorial.mp4`)
**ตำแหน่งที่ตั้งเป้าหมาย:** `docs/product/ONBOARDING.md`

**สคริปต์การดำเนินการ:**

1. เริ่มต้นที่ภาพรวม NOC (NOC Overview) สังเกตความผิดปกติที่เป็นสีแดงบนกราฟ **แบนด์วิดท์เครือข่าย (Network Bandwidth)**
2. **คลิก** ที่ความผิดปกตินั้น (สิ่งนี้จะกระตุ้นการทำงานของ Grafana Data Link)
3. หน้าจอจะเปลี่ยนไปอย่างราบรื่นไปยังแดชบอร์ด **การเจาะลึกข้อมูลเชิงวิศวกรรม (Engineering Drill-Down)**
4. เปิดเมนูแบบเลื่อนลง `$machine_id` ที่มุมซ้ายบนแล้วพิมพ์ `SRV-901`
5. แดชบอร์ดทั้งหมดจะเรนเดอร์ใหม่อย่างรวดเร็ว (ขับเคลื่อนโดย TimescaleDB CAGGs)
6. เลื่อนเมาส์ไปเหนือแผนภูมิ **ความผิดปกติของค่า Z-Score (Z-Score Anomaly)** ซึ่งแสดงช่วงเวลาที่เกิดการพุ่งขึ้นของ CPU อย่างแม่นยำ
7. จบฉาก

---

## ฉากที่ 3: การวางแผนความจุเชิงคาดการณ์ (AIOps)

**ประเภทเนื้อหา:** GIF ความยาว 10 วินาที (`predictive-aiops.gif`)
**ตำแหน่งที่ตั้งเป้าหมาย:** ส่วนคุณสมบัติใน `README.md`

**สคริปต์การดำเนินการ:**

1. เปิด [การวางแผนความจุ](http://localhost:3000/d/ims-capacity)
2. โฟกัสกรอบการบันทึกหน้าจอให้จำกัดเฉพาะที่เกจวัด **จำนวนวันก่อนที่จะเต็ม (Days Until Full)** และกราฟ **การคาดการณ์การถดถอยเชิงเส้น (Linear Regression Forecast)**
3. เลื่อนเมาส์ไปเหนือจุดตัดที่เส้นแนวโน้มไปถึง 100% Tooltip ควรอ่านอย่างชัดเจนว่า "วันที่คาดการณ์ว่าจะเต็ม: 12 ต.ค. 2026"

---

## ฉากที่ 4: กระดานแจ้งเตือนแอนดอนสำหรับผู้ปฏิบัติงาน (พื้นที่โรงงาน)

**ประเภทเนื้อหา:** GIF ความยาว 5 วินาที (`andon-board.gif`)
**ตำแหน่งที่ตั้งเป้าหมาย:** `SOP_OPERATOR.md`

**สคริปต์การดำเนินการ:**

1. เปิด [LDI Operator Andon](http://localhost:3000/d/ims-ldi-operator-andon)
2. ใช้สคริปต์ฐานข้อมูล `make test-load` เพื่อจำลองการเกิดข้อผิดพลาด
3. บันทึกช่วงเวลาที่แดชบอร์ดกะพริบเปลี่ยนจากสีเขียวเป็นสีแดง
4. สิ่งนี้แสดงให้เห็นถึงความหน่วงแฝงที่ต่ำมาก (< 2 วินาที) ของไปป์ไลน์การนำเข้าข้อมูล Node-RED
