# Factory Twin — 操作员指南

如何解读一楼孪生，而不做超出数据的解读。

配合 **[重建方法](FACTORY_TWIN_RECONSTRUCTION.md)**、**[运行时架构](FACTORY_TWIN_ARCHITECTURE.md)** 与
**[安全模型](FACTORY_TWIN_SECURITY_MODEL.md)** 阅读（这三份文档以英文原文为准）。

> [!IMPORTANT]
> 本页最重要的一点：**屏幕上看到的并不都是同一类事实。** 建筑、柱子与墙体读自 CAD；设备位置与朝向读自 CAD；
> 部分设备的*尺寸*尚无法确定；没有任何受监控设备被绘制在平面图上；也没有任何对象被确认为某台实际设备。
> 界面的设计正是为了把这些区分开。把它们当作同一幅图来解读，正是本系统要防止的错误。

---

## 四项区分

这并非咬文嚼字。任何一项被混为一谈，都会导致一个具体的错误决策。

| 区分 | 混为一谈会造成什么后果 |
|---|---|
| **观察到 ≠ 已确认** | 检测到的柱子或位置有证据支撑，但**不带任何身份**。把观察到的位置当作已知设备，会把实时状态归到无人识别过的设备上。 |
| **模拟 ≠ 真实** | 设备*状态*是真实遥测。设备*位置*来自 CAD，但没有任何受监控设备被放置或映射到这些位置。按屏幕上的位置去现场找某台特定设备，会找错地方。 |
| **推算 ≠ 实测** | 层高由图纸上标注的标高推算而来，楼板下的净高则完全未知。把推算值当作净空高度使用，属于人身安全层面的错误。 |
| **未知 ≠ 缺失** | 空白的高度、未映射的位置或不存在的墙体，表示*没有任何数据源*，而不是有人漏填。没有任何事项在等待处理；只是它不存在。 |

## 屏幕布局

界面各部分**以停靠方式排列**。标题栏、状态条、平面图与检查抽屉都是布局轨道，而非浮动窗口，因此平面图上不会覆盖任何内容。
打开抽屉会让平面图变窄，但绝不会遮住它。

```
HEADER          factory identity · view controls · data quality · build id · Inspection
STATUS STRIP    Off  Down  Idle  Initial  PM  Stop  Run  Undefined  |  Unmapped
FLOOR                                                        INSPECTION DRAWER
                the plan or the model, full width              factory KPIs
                                                               layers
                CONTEXT PANEL appears here, bottom-left,       machine states
                only after you select something                evidence
                                                               devices
                                                               diagnostics
```

**上下文面板（context panel）** 是唯一允许覆盖在平面图上的元素，只在选中对象后出现，尺寸有上限且可滚动。
回归测试会在 5 种视口——1366×768、1920×1080、2560×1440、3840×2160 以及竖屏 600×1000——点击检测画布中心，
只要该位置不是画布就判定失败。

宽度低于 900 px 时，抽屉改为覆盖而非停靠：在 600 px 的屏幕上保留 340 px 的轨道会让平面图无法阅读。
在任何宽度下都成立的约定是：**平面图区域绝不会为了腾出空间而扩展**，且抽屉始终可以关闭。

**屏幕上显示构建标识。** 标题栏中的 `build …` 标签是当前运行构建的指纹，从 `/api/build` 获取，
在启动时根据运行镜像中实际源文件的字节计算得出。它不是写死在页面里的常量——常量只会显示上次有人编辑时写入的内容，
而这正是过期部署无法被察觉的原因。两个服务显示相同指纹，说明它们运行的是完全相同的代码。

## 视图

提供三个相机预设，**以 2D 为先**。当前这个孪生的目标是物理准确性，因此平面图是主视图。
**切换视图只改变相机，不改变其他任何东西**——没有任何视图会移动对象、修改坐标或改变证据状态，
回归测试会断言每次切换前后渲染出的坐标字符串逐字节相同。

| 视图 | 取景 | 用途 |
|---|---|---|
| **2D Plan** | **默认视图。** 正上方俯视：CAD 平面图——外轮廓、按实测厚度绘制的墙体、柱子、开口、区域与设备。 | 将孪生与图纸比对；像读图纸一样读平面。 |
| **3D** | 斜视角，适配整个楼层。 | 向管理层/NOC 做整体演示；以体量理解建筑。 |
| **Fit floor** | 以实测的建筑外轮廓取景，所有结构几何都在画面内。 | 旋转后回到已知的取景。 |

这三者是同一个场景、同一套坐标，只是观察角度不同——并非各自独立的图纸——因此平面图与 3D 模型在墙的位置上永远不会有分歧。

手动调校的 **Operator** 相机已被移除。它取景的是一个已不复存在的合成设备网格，只会框住空地。

**在定义视图所需的数据到达之前，视图按钮保持禁用。** 按钮被禁用说明实测的建筑外轮廓尚未加载——常见原因是全新克隆的环境中没有私有几何数据。

**Reset camera** 会重新应用当前视图的取景，但不会切换视图：处于哪个视图由你决定；旋转之后相机停留在哪里则不算数。

## 图层

每个开关对应一类证据，而不是为了方便而分组。隐藏图层只会隐藏网格，绝不会移除对象、改变数量或改变 API 结果。

| 图层 | 包含内容 | 证据类别 |
|---|---|---|
| **Floor shell** | 楼板、实测的建筑外轮廓、测绘网格线 | MEASURED 外轮廓 |
| **Columns** | 从 CAD 读取的结构柱 | MEASURED_CAD |
| **Walls and openings** | 内墙与隔墙，以及门、窗和风淋室 | 平面与厚度为 MEASURED_CAD；**高度为 PRESENTATION_ONLY** |
| **Functional zones** | 仅包含通过验证的工艺/功能区域 | OBSERVED_CAD（仅限验证通过的层级） |
| **Equipment** | CAD 块引用：344 个位置，其中 270 个有实测尺寸，其中 213 个按 CAD 自身的轮廓而非方框绘制 | 位置、朝向与尺寸为 MEASURED_CAD；74 个尺寸为 UNRESOLVED，以统一标记绘制 |
| **Raw CAD reference** | 图纸自身的线条，绘制在重建结果之上 | 不是楼层的一个图层——而是用来核对楼层的**源头** |

参考图层与上方图层之间用分隔线隔开，因为它属于另一类东西。其他每个图层都是模型：经过配对、合并与分类的几何。
参考图层则是图纸本身，没有经过任何上述处理，以细的琥珀色线条绘制在模型之上，便于肉眼比对。两者不一致时，以图纸为准。

该图层默认关闭，首次打开时才会获取数据，因此普通的楼层视图无需为它付出代价。它也会说明自己省略了什么：
393 个门、窗与风淋室的**块引用未展开**，所以你会看到墙上的开口，但看不到门扇；与本图纸共用 modelspace 的设备详图被完全排除。

每个开关都带有实时计数——例如区域开关会显示已验证与被保留的数量，设备开关会显示有多少尺寸为 UNRESOLVED。
**被保留的区域在任何开关设置下都不会被渲染**；它们未通过验证或涉及尚未解决的冲突，开关无权将其提升。

## 解读设备

楼层上的每个资产都来自一个 CAD 块引用，且每个都带有**强度不同的两项声明**：

| | 声明 | 绘制方式 |
|---|---|---|
| **位置与朝向** | `MEASURED_CAD`——由图纸自身的 `INSERT` 记录给出。没有任何描摹、吸附、平均或拟合。 | 它在哪里、如何摆放 |
| **尺寸** | 344 个资产中 270 个为 `MEASURED_CAD`（在块自身的几何上经坐标变换后测得）；74 个为 `UNRESOLVED` | 实心、颜色较浅的底板（其中 213 个按 CAD 自身轮廓绘制）——或一个统一大小的小标记 |

**统一大小的标记表示 CAD 没有确定该设备的尺寸。** 该块小于设备尺度，或者它绘制的是一个区域而非单个资产，
因此其几何无法被当作设备本体来读取。系统不会以默认方框替代。每个 unresolved 标记都刻意保持相同大小：它绝不能被误认为是测量值。

**所有资产的高度均未知。** 平面图不包含设备标高，因此所有内容都是平面底板，绝不会绘制成暗示某个无人读取过的高度的立体。

## 已不再绘制的内容

有三类内容已被移除，而且每一类都是在数据路径上移除，而非仅仅隐藏：

- **每一台受监控设备。** 孪生过去会在一个合成网格上绘制全部 23 台设备。相关路由、计算、网格以及据此确定尺寸的楼板都已删除。
  在读自 CAD 的楼层上，一个编造的位置与一个实测的位置并列时，肉眼无法区分。遥测仍然真实，仍每 5 秒轮询一次；
  它驱动状态条与设备列表，但不会为平面图上的任何对象着色。
- **243 个栅格设备位置。** 从印刷图纸的扫描件数字化而来：左右位置、尺寸与朝向都来自栅格，而非图纸。
  它们作为已被取代的记录保留在私有文档中，不在任何地方提供。
- **编造的设备外形。** 从一张无人测量过的形状表中选出的机身，叠加在那些栅格位置之上——两层未经测量的声明叠在一起，
  却以与旁边 CAD 数据相同的视觉权重渲染。

场景中没有任何对象能打开设备下钻，因为场景中没有任何对象*是*一台设备。下钻必须从一个位置开始，
而这一层楼上没有任何位置通过权威记录与某台设备关联。

**栅格示意图视图**也已从本页移除。该转录数据本身仍然存在，`/api/floor-schematic` 仍在提供它，
但规范的 Factory Twin 是 CAD 楼层，而把不按比例的图纸混入同一页面，正是栅格几何曾经泄漏到物理视图中的原因。

## 状态条——恰好八种状态

这些是工厂自己的用语，而不是本视图自创的监控术语。看这块看板的操作员与看产线 HMI 的操作员，会对同一台设备看到同一个词。

| 状态 | 含义 |
|---|---|
| **Off** | *无数据源。* 已断电。本 schema 中没有任何列会上报该状态。 |
| **Down** | 已映射资产上存在处于活动状态的 Critical 或 Major 告警。 |
| **Idle** | 已映射资产存在且在上报数据，但未运行。 |
| **Initial** | *无数据源。* 预热或作业开始阶段。 |
| **PM** | *无数据源。* 计划性维护。 |
| **Stop** | *无数据源。* 被有意停机。 |
| **Run** | 已映射资产正在运行，且没有活动告警。 |
| **Undefined** | 已映射资产，但证据不足以确定状态。 |

其中四种标记为 **NO SOURCE**，显示为**短横线，而不是零**。这是关于*系统*而非现场的陈述：本部署没有任何列能点亮这些指示灯。
零是一个测量结果（"没有设备处于 PM"）；短横线才是事实（"本系统无法告诉你"）。

**Unmapped 不是第九种状态。** 它位于分隔符之后，因为它是关于*记录*的事实——该资产与任何设备都没有权威关联——而不是关于设备本身。
未映射的资产既不是 Off，也不是 Undefined；任何设备状态都不适用于它。

无论屏幕上显示什么，以下两条规则都成立：

- **无法确定状态的设备显示为 Undefined**，绝不会显示为看似合理的 Idle、Off 或 Run。查询失败绝不能被读成一台健康的设备，也不能被读成一台已断电的设备。
- **状态必须基于权威的设备映射。** 位置、编号与名称相似性都不能产生映射。由于**目前已确认的映射为 0，这层楼上的每个实体资产都是 Unmapped**，
  也没有任何实时状态被绘制在它们上面。

每一行除了颜色还有独特的符号，因此这套术语在单色屏幕、投影仪以及色觉障碍的情况下依然可读。

已被移除的状态——NORMAL、WARNING、CRITICAL、OFFLINE、STALE DATA、MAINTENANCE、PRESENTATION ONLY——是本视图自创的。
若其中任何一个重新出现在看板上，回归测试就会失败。

## 证据图例

在面板中打开 **Evidence legend**。每种状态都以**符号 + 文字**显示，颜色仅起强化作用：

| 符号 | 状态 | 含义 |
|---|---|---|
| ▣ | **MEASURED** | 从数据源读取并经交叉核对。 |
| ▲ | **DERIVED** | 由实测输入计算得出，而非直接读取。 |
| ◆ | **OBSERVED** | 已检测并经目视确认；**不声明任何身份**。 |
| ◇ | **SIMULATED** | 有意设定为非真实。 |
| ? | **UNKNOWN** | 不存在数据源，并非待处理。 |
| ✓ | **CONFIRMED** | 权威确认。**本构建中没有任何内容是 CONFIRMED。** |

颜色从来不是唯一的信息通道。在单色屏幕上或任何色觉缺陷的情况下，符号与文字依然都能表达状态。

## 检查器（Inspector）

将鼠标悬停在对象上会打开检查器。它只报告安全的汇总元数据：**对象类型、证据状态、来源类别、置信度、映射状态、高度状态。**

它有意不暴露文件名、文件系统路径、源文档内容、厂商名称、工艺名称或凭据。如果你需要的值没有显示，那是按设计被保留——见
**[安全模型](FACTORY_TWIN_SECURITY_MODEL.md)**。

你会看到的内容及其含义：

| 字段显示 | 含义 |
|---|---|
| `UNMAPPED` | 没有权威记录将该位置与某台设备关联。这是目前**所有**资产的状态。 |
| Footprint `UNRESOLVED — no size is claimed` | CAD 没有确定该资产的尺寸。不声明任何尺寸，只绘制统一标记。 |
| Position evidence `MEASURED_CAD` | 直接读自 CAD 的 `INSERT`：插入点与旋转角都是图纸自身的数据。 |
| Footprint evidence `MEASURED_CAD — the block's own geometry, transformed and measured` | 尺寸是在块自身的几何上，经完整 `INSERT` 链变换后测得。 |
| Footprint evidence `UNRESOLVED — not established by the CAD` | 该资产不存在尺寸证据。 |
| height `unknown — not in evidence` | 平面图不包含设备标高。没有做任何估算。 |

检查器把位置与尺寸显示为**两行，并各自带有独立的证据等级**，因为它们是同一条记录上强度不同的两项声明。把它们当作一项来读，正是这种布局要防止的错误。

## 无障碍

- **键盘：** 视图按钮、重置按钮、Inspection 开关、每个图层复选框以及每个展开项都是原生控件，可用 <kbd>Tab</kbd> 访问，
  用 <kbd>Space</kbd> / <kbd>Enter</kbd> 激活。相机旋转属于指针交互，但三个视图预设与重置按钮让仅用键盘的用户无需旋转也能获得完整的取景。
- **可见焦点：** 焦点轮廓明确可见，而不是被隐藏的默认样式。
- **对比度：** 标题栏、状态条与抽屉中的文字在所用字号下，与面板背景的对比度达到 4.5:1。
- **绝不只靠颜色：** 每种证据状态都带有符号与文字。
- **实时区域：** 检查器以礼貌方式播报，不会打断用户。

已在 1366×768、1920×1080、2560×1440、3840×2160 以及竖屏 600×1000 视口下验证。见 **[视觉 QA](FACTORY_TWIN_VISUAL_QA.md)**。

---

## 本视图无法告诉你的内容

不必寻找这些内容；它们之所以不存在，是因为没有数据源。

- 任一资产对应哪台实际设备（**已确认映射为 0**）。
- 344 个资产中 74 个的尺寸（**尺寸 UNRESOLVED**）。
- 电梯坑。
- 净空高度，或任何设备的高度。
- 完整的设备清单。

**[证据要求](FACTORY_TWIN_EVIDENCE_REQUIREMENTS.md)** 明确说明了解锁每一项所需的条件。
