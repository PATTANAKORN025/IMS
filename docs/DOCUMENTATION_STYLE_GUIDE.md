# Documentation Style Guide

All IMS documentation must adhere to the following hyper-scaler standards:

## 1. "Auto-Clarity" Rule
Cut the fluff. Remove filler words ("just", "really", "basically"). Get straight to the technical substance. 

## 2. Active Voice
- **Bad**: The dashboard is reloaded by the script.
- **Good**: The script reloads the dashboard.

## 3. Use GitHub Alerts
Highlight critical information visually:
- `> [!NOTE]` for context.
- `> [!WARNING]` for destructive actions.
- `> [!IMPORTANT]` for core requirements.

## 4. Header Nesting
Do not nest deeper than H3 (`###`). If you need deeper structure, use bold text or lists.
