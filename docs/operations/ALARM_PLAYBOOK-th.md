# สมุดคู่มือการจัดการการแจ้งเตือนและสัญญาณเตือน IMS

> **จุดประสงค์:** ขั้นตอนการตอบสนองเบื้องต้นที่จับคู่กับการแจ้งเตือนและรหัสสัญญาณเตือนที่ระบบนี้สร้างขึ้นจริง รหัสและชื่อกฎทุกรายการด้านล่างได้รับการตรวจสอบโดยตรงกับฐานข้อมูลจริงและไฟล์กฎการแจ้งเตือนที่เตรียมไว้เมื่อ 2026-08-10 — แทนที่เวอร์ชันก่อนหน้าที่ใช้รหัสสมมติ (`SYS-001`, `NET-002`, `LDI-001`) ซึ่งไม่มีอยู่จริงในระบบนี้
>
> IMS มี **การแจ้งเตือนสามระดับที่แตกต่างกัน** และใช้คำศัพท์ที่แตกต่างกัน — ห้ามสับสน:
>
> 1. **รหัสสัญญาณเตือนเครื่องจักร LDI** — รหัสตัวเลขจากอุปกรณ์จริง/จำลอง จัดเก็บใน `public.ldi_alarm_log` และจัดหมวดหมู่ใน `public.ldi_alarm_ms_code` ดู `ALARM_SEVERITY_GUIDE.md` สำหรับอนุกรมวิธานแบบเต็ม
> 2. **กฎการแจ้งเตือนดั้งเดิมของ Grafana** — กฎเกณฑ์/ความผิดปกติที่ Grafana ประเมินกับฐานข้อมูล แบ่งเป็นเฉพาะ LDI (`monitoring/grafana/provisioning/alerting/ldi-rules.yml`) และโครงสร้างพื้นฐาน (`rules.yml`)
> 3. **กฎ Prometheus/Alertmanager** — การตรวจสอบการตรวจสอบของแพลตฟอร์มเอง (`monitoring/prometheus/rules/ims-alerts.yml`) — ไปป์ไลน์ของ IMS ทำงานปกติหรือไม่ ไม่ใช่ "เครื่องจักรอยู่นอกสเปคหรือไม่"

ทั้งสามเส้นทางผ่านการจัดส่งแบบเดียวกัน: การแจ้งเตือนดั้งเดิมของ Grafana ทริกเกอร์โดยตรง; การแจ้งเตือน Prometheus ผ่าน Alertmanager → `/alert-webhook` ของ Node-RED (`nodered_data/flows/alerting.json`) ซึ่งจัดรูปแบบเพย์โหลด LINE Messaging API และ MS Teams **การส่งไปยัง LINE/Teams จริงต้องใช้ `LINE_CHANNEL_ACCESS_TOKEN` และ `TEAMS_WEBHOOK_URL` ซึ่งไม่มีใน `.env` โดยการออกแบบ** — ตรรกะการจัดรูปแบบและความพยายามจัดส่งถูกต้องและแจ้งเมื่อล้มเหลว (`node.error()` + สถานะสีแดงค้างใน Node-RED) แต่จะไม่ถึงผู้ใช้จนกว่าผู้ปฏิบัติงานจะกำหนดค่าข้อมูลรับรองจริงตาม `docs/admin/ADMIN_MANUAL.md`

## 2. กฎการแจ้งเตือนดั้งเดิมของ Grafana — LDI (`ldi-rules.yml`)

| กฎ                                               | ความหมาย                                                                                                                                               | สิ่งที่ต้องตรวจสอบ                                                                          |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| **LDI Quality Drift — Max PE exceeds tolerance** | ตัวอย่าง PE (position error) ที่แย่ที่สุดของเครื่องจักรละเมิดพิกัด `pe_setting`                                                                        | `LDI Engineering Analytics` → พาเนล SPC สำหรับเครื่องจักรที่ได้รับผลกระทบ                   |
| **LDI Process Capability — Cpk below 1.33**      | Cpk ตาม PE ลดลงต่ำกว่ามาตรฐานอุตสาหกรรมที่ 1.33                                                                                                        | แดชบอร์ดเดียวกัน; ตรวจสอบว่าเป็นการเบี่ยงเบนครั้งเดียวหรือต่อเนื่อง — ดู `LDI_SPC_GUIDE.md` |
| **LDI Quality Drift — Max JE exceeds tolerance** | เช่นเดียวกับการเลื่อนของ PE สำหรับ JE (judgment error)                                                                                                 | แดชบอร์ดเดียวกัน, พาเนล JE                                                                  |
| **LDI JE Process Capability — Cpk below 1.33**   | Cpk ตาม JE ต่ำกว่า 1.33                                                                                                                                | แดชบอร์ดเดียวกัน                                                                            |
| **LDI Machine Alarm — new alarm in database**    | ข้อมูลใหม่เข้าสู่ `ldi_alarm_log` นี่คือกฎครอบคลุม "มีบางอย่างเกิดขึ้น" — ตรวจสอบหัวข้อ 1 สำหรับรหัสเฉพาะ                                              | Operator Andon Board                                                                        |
| **LDI Temperature High — above 24°C spec limit** | กฎเกณฑ์ขีดจำกัดคงที่ ไม่ใช่ Z-Score anomaly — ดูบันทึกใน `LDI_RCA_GUIDE.md` ว่าไม่มีพาเนลวิเคราะห์ความผิดปกติเชิงสถิติฝั่ง LDI มีเพียงขีดจำกัดคงที่นี้ | พาเนลอุณหภูมิ `LDI Engineering Analytics`                                                   |

## 3. กฎการแจ้งเตือนดั้งเดิมของ Grafana — โครงสร้างพื้นฐาน (`rules.yml`)

| กฎ                                                              | ขอบเขต                                                                                                                                                                                                                                                                                                     |
| --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| High CPU / RAM / Disk Usage                                     | ขีดจำกัดทรัพยากรเซิร์ฟเวอร์/เวิร์กสเตชัน                                                                                                                                                                                                                                                                   |
| High Temperature                                                | อุณหภูมิแชสซีเซิร์ฟเวอร์                                                                                                                                                                                                                                                                                   |
| High Network Error Rate / Network Packet Drops / Interface Down | ความสมบูรณ์ของอินเทอร์เฟซเครือข่าย                                                                                                                                                                                                                                                                         |
| Bandwidth Saturation Forecast                                   | การคาดการณ์ — แนวโน้มความจุไปสู่ความอิ่มตัว ยังไม่ละเมิด                                                                                                                                                                                                                                                   |
| CPU Z-Score Anomaly (>3σ) / Temperature Z-Score Anomaly (>3σ)   | การตรวจจับความผิดปกติทางสถิติ — โครงสร้างพื้นฐานเท่านั้น **ไม่มีพาเนล Z-Score เทียบเท่าในฝั่ง LDI** (ดู `LDI Temperature High` ด้านบนที่เป็นขีดจำกัดคงที่แทน)                                                                                                                                              |
| LDI Vibration Critical                                          | **หยุดชั่วคราว** `ldi_metrics.vibration` ยืนยันแล้วว่าเป็น `0` เสมอสำหรับอุปกรณ์ LDI ทุกตัว (ช่องว่างที่ทราบในไปป์ไลน์ `ldi_metrics` เดิม ไม่ใช่ `ldi_data` — ดูช่องว่างที่ทราบใน `ARCHITECTURE.md`) กฎนี้ไม่สามารถทำงานได้จนกว่าจะได้รับการแก้ไข; มันถูกหยุดชั่วคราวแทนที่จะปล่อยทิ้งไว้ให้ไม่ทำงานเงียบๆ |

ตรวจสอบการแจ้งเตือนโครงสร้างพื้นฐานเริ่มจาก `NOC Overview` หรือ `Engineering Drill-Down`

## 4. กฎ Prometheus / Alertmanager (`ims-alerts.yml`)

กฎเหล่านี้ตรวจสอบ **ความสมบูรณ์ของไปป์ไลน์ IMS เอง** ไม่ใช่สถานะเครื่องจักรหรือเซิร์ฟเวอร์ — "ระบบตรวจสอบเองทำงานอยู่หรือไม่"

| กฎ                                                                        | ความหมาย                                                                                                                                     | การตอบสนองแรก                                                                                                                                       |
| ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PrometheusDown` / `AlertmanagerDown` / `TargetDown` / `HighScrapeErrors` | ส่วนประกอบสแต็กการตรวจสอบไม่สมบูรณ์                                                                                                          | ตรวจสอบ `docker ps` สำหรับคอนเทนเนอร์ที่เกี่ยวข้อง; ดู `INCIDENT_RESPONSE.md`                                                                       |
| `ServiceDown` / `ServiceHighLatency` / `SLABreachWarning`                 | การล้มเหลวของการตรวจสอบ blackbox-exporter เทียบกับปลายทางเป้าหมาย (เช่น `/api/health` ของ Grafana)                                           | ตรวจสอบบริการปลายทางโดยตรง; ระวังนี่อาจเป็นผลชั่วคราวจากการจงใจสร้างคอนเทนเนอร์ใหม่ — ดูหลักฐานจากการซ้อม 2 ใน `DR_TEST_PLAN.md` สำหรับตัวอย่างจริง |
| `SSLCertExpiring`                                                         | ใบรับรอง TLS ของปลายทางใกล้หมดอายุ                                                                                                           | ต่ออายุก่อนหมดอายุ                                                                                                                                  |
| `Watchdog`                                                                | ฮาร์ทบีทที่ทำงานเสมอเพื่อยืนยันว่าการส่งข้อมูลของ Alertmanager ทำงาน — **ไม่ใช่** เหตุการณ์จริง ยกเว้นเมื่อสแกนหาการแจ้งเตือนจริงที่เกิดขึ้น |
| `PipelineDataStalled` / `PipelineDataDegraded` / `PipelineHighErrorRate`  | ความสมบูรณ์ของไปป์ไลน์การนำเข้าข้อมูล Node-RED — ข้อมูลหยุดชะงัก/ลดลง/ข้อผิดพลาดสูง                                                          | แดชบอร์ด `Meta-Monitoring`; ตรวจสอบบันทึก `ims-node-red` สำหรับรูปแบบความล้มเหลวเฉพาะ (ดูตัวอย่างการแก้ไขใน `INCIDENT_RESPONSE.md`)                 |
| `CircuitBreakerOpen`                                                      | เซอร์กิตเบรกเกอร์ SNMP ของอุปกรณ์ตัดวงจร (CLOSED→OPEN หลังล้มเหลวซ้ำๆ)                                                                       | ตรวจสอบการเชื่อมต่อของอุปกรณ์นั้น; เบรกเกอร์จะรีเซ็ตเองเป็น HALF_OPEN หลังจากระบายความร้อน                                                          |
