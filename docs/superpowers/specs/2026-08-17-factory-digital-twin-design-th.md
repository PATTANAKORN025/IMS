# IMS LDI — Factory Digital Twin (2D Canvas): การออกแบบ

> สถานะ: อนุมัติโดยผู้ใช้เมื่อ 2026-08-17, ยังไม่ได้ดำเนินการติดตั้ง.
> ตำแหน่งในแผนงาน (การจัดลำดับตามที่ผู้ใช้กำหนด, ห้ามสลับลำดับ):
> Real DB → Machine State Model → 2D Canvas → Drill-down → Production/Compliance →
> Performance Validation → 3D Digital Twin สเปคนี้ครอบคลุมทุกอย่างจนถึง
> Performance Validation ส่วน 3D นั้นอยู่นอกเหนือขอบเขตอย่างชัดเจน

## วัตถุประสงค์

"ดูว่าโรงงานกำลังผลิตอะไร, แต่ละเครื่องจักรกำลังทำอะไร, ตั้งอยู่ที่ไหน, เกิดปัญหาอะไรขึ้นบ้าง, และปัญหาเหล่านั้นส่งผลกระทบต่อ Production/Compliance อย่างไร" ไม่ใช่แดชบอร์ดที่เน้นกราฟหนักๆ — แต่เป็นการแสดงภาพรวมการทำงานของโรงงานแบบมองเห็นได้ทันที (at-a-glance) พร้อมความสามารถในการเจาะลึก (drill-down) ไปยังแดชบอร์ดรายละเอียดที่มีอยู่เดิม

## ข้อกำหนดหลัก (กำหนดโดยผู้ใช้, รักษาเจตนาดั้งเดิมทุกประการ)

- ห้ามแก้ไข `ims-ldi-manufacturing.json` (Manufacturing Command Center)
- ห้ามแก้ไข `ims-ldi-operator-andon.json` (Andon Board)
- ห้ามใช้ข้อมูลจำลอง (mock/simulated) ใดๆ ในแดชบอร์ดนี้
- ใช้แหล่งข้อมูลจริงเท่านั้น (`timescaledb`)
- สถานะเครื่องจักร, การแจ้งเตือน, และสถานะการผลิตต้องสามารถตรวจสอบย้อนกลับไปยังแถวข้อมูลจริงในฐานข้อมูลได้ — รูปแบบคิวรีทั้งหมดต้องนำกลับมาใช้จากแดชบอร์ดที่มีอยู่และได้รับการพิสูจน์แล้ว ไม่ใช่สร้างขึ้นมาใหม่
- `machine_id` ต้องไม่ซ้ำกัน
- `board_id` ต้องไม่ซ้ำกัน
- `board_no` ต้องผ่านการตรวจสอบความถูกต้อง
- ทุกโหนดต้องสามารถเจาะลึก (drill-down) ได้
- ทุกสีต้องมีการบันทึกความหมายเชิงความหมาย (semantic meaning) (ไม่มีการใช้รหัสสี hex ที่ไม่ได้บันทึกไว้)
- ห้ามใช้ Grafana CSS ที่ไม่ได้บันทึกไว้
- ห้ามติดตั้งปลั๊กอิน Grafana ภายนอกเพิ่มเติมจากที่ติดตั้งไว้แล้ว (`GF_INSTALL_PLUGINS` ใน `docker-compose.yaml`)
- ต้องกำหนดงบประมาณด้านประสิทธิภาพ (Performance budget) ก่อนสร้าง ไม่ใช่หลังจากสร้างเสร็จ

## ข้อค้นพบจริงที่มีอิทธิพลต่อการออกแบบนี้ (ตรวจสอบกับ DB/Grafana ที่ใช้งานจริงในเซสชันนี้, ไม่ได้ตั้งสมมติฐาน)

1. **Canvas panel เป็นส่วนหลัก/ภายในของ Grafana 13.1.1** — ยืนยันผ่าน `GET /api/plugins`, `signature: internal` ไม่จำเป็นต้องติดตั้งปลั๊กอินใหม่; ตอบสนองข้อจำกัด "ห้ามใช้ปลั๊กอินภายนอก" ได้โดยปริยาย
2. **ไม่มีพิกัดแผนผังชั้น (floor-plan) จริงอยู่เลย** `public.devices.location` เก็บเฉพาะป้ายระบุโซนแบบหยาบๆ 5 โซนเท่านั้น: `Site A - Zone 1`, `Site A - Zone 2`, `Site A - Zone 3`, `Site B - Zone 1`, `Site B - Zone 2` ไม่มีคอลัมน์ x/y หรือ lat/long ใดๆ ในสคีมา. เลย์เอาต์ที่เลือก: บล็อกโซน 5 บล็อกพร้อมป้ายกำกับบน Canvas, เครื่องจักรถูกจัดวางในรูปแบบกริดภายในโซนจริงของมัน (ตัวเลือกที่ผู้ใช้อนุมัติ) _ตำแหน่ง_ (position) ของโหนดเป็นการตั้งค่า canvas ด้วยตนเอง (เหมือนกับลำดับไทล์ (tile) แบบ repeat-panel ของ Andon); _สถานะ_ (status) ของโหนดเป็นคิวรีแบบสด สิ่งเหล่านี้แตกต่างกันและต้องไม่นำมาปะปนกันใน JSON ของ panel หรือคำอธิบาย
3. **มีเครื่อง `device_type='ldi'` ลงทะเบียนไว้ 23 แถว แต่มีเพียง 10 เครื่องที่รายงานผลจริง**
   `SELECT eqp_id, COUNT(*) FROM ldi_data WHERE time > NOW() - INTERVAL '24 hours' GROUP BY eqp_id` ส่งคืนค่า `LDI-01`..`LDI-10` พอดิบพอดี ส่วนอีก 13 รายการ (`LDI-B07` ระบบเก่า, `LDI-B05/LD2`, `LDI-B01/LD2`, `LDI-A01`, `LDI-A02`, `LDI-A03/02`, `LDI-A05/02`, `LDI-B03/2`) มี `enabled=true` ในระบบทะเบียน แต่ไม่เคยเขียนลง `ldi_data` — เป็นรายการที่ตายแล้ว/ชื่อแทน (alias) Canvas จะแสดงเฉพาะ 10 เครื่องที่รายงานผลจริงเท่านั้น แถวทะเบียนที่ไม่มีอยู่จริง (ghost) 13 รายการ เป็นช่องว่างด้านคุณภาพข้อมูลที่มีอยู่ก่อนแล้ว อยู่นอกเหนือขอบเขตของแดชบอร์ดนี้ บันทึกไว้ที่นี่เพื่อไม่ให้ถูกค้นพบใหม่โดยไม่รู้ตัวในภายหลัง
4. **`board_id` ว่างเปล่าใน 100% ของแถวข้อมูลจริง**
   `SELECT COUNT(DISTINCT board_id) FROM ldi_data WHERE time > NOW() - INTERVAL '24 hours'` → มี 1 ค่าที่ไม่ซ้ำกันใน 19,043 แถว (สตริงว่าง) ข้อกำหนดที่ว่า "board_id ต้องไม่ซ้ำกัน" ไม่สามารถทำได้จริงตามที่ระบุ — คอลัมน์นี้ไม่ได้ถูกเติมข้อมูลโดยไปป์ไลน์การนำเข้าข้อมูลจริง
   **การตัดสินใจ (ผู้ใช้อนุมัติ): ใช้ `log_id` แทน** — ตรวจสอบแล้วว่า 100% ไม่เป็นค่าว่าง และ 100% ไม่ซ้ำกัน (19,119/19,119) ในช่วงเวลาเดียวกัน แดชบอร์ดจะระบุป้ายกำกับฟิลด์นี้ว่า "Event ID (log_id)" แทน "Board ID" เพื่อหลีกเลี่ยงการสื่อถึงความสามารถในการติดตามบอร์ดที่ไม่มีอยู่จริง
5. **`board_no`/`total_board` เป็นข้อมูลจริงและสมบูรณ์**
   0 จาก 19,053 แถวที่ละเมิดเงื่อนไข `board_no <= total_board`; 0 ค่าติดลบ; 0 ค่า `total_board` ที่ไม่เป็นบวก; มีค่า `board_no` ที่ไม่ซ้ำกัน 233 ค่า; `total_board` ที่ไม่ซ้ำกัน 74 ค่า ข้อมูลนี้สามารถใช้งานได้จริงเพื่อเป็นตัวบ่งชี้ความคืบหน้าการผลิตต่อเครื่องจักร (`board_no/total_board`) "board_no ต้องผ่านการตรวจสอบความถูกต้อง" สอดคล้องกับการตรวจสอบนี้ ซึ่งจะรันในขั้นตอนการสร้าง (build time) และตรวจสอบอีกครั้งใน Performance Validation
6. **เงื่อนไข (contract) การแบ่งระดับคิวรี (query-tiering) ที่มีอยู่จะไม่มีการเปลี่ยนแปลง**
   `GRAFANA_DESIGN_SYSTEM.md` §10 / `tests/lint/query-budget-linter.js`:
   `ldi_data` แบบดิบ (raw) มีไว้สำหรับการค้นหาค่าล่าสุดเท่านั้น (`LIMIT 1` / `DISTINCT ON`); การสแกนแบบช่วง (range scans) ต้องผ่าน `ldi_data_1m` (≤6h), `_15m` (6h–2d), หรือ `_1h` (>2d) คิวรีโหนดของ Canvas ทุกตัวเป็นการค้นหาค่าล่าสุดเทียบกับ `ldi_data` ดิบ (รูปแบบเดียวกับ `v_ldi_machine_latest_full`, ซึ่ง Andon ใช้อยู่แล้ว) — ไม่จำเป็นต้องมีกฎการแบ่งระดับใหม่ เงื่อนไขที่มีอยู่ครอบคลุมเรื่องนี้แล้ว
7. **งบประมาณด้านประสิทธิภาพมีอยู่จริง**
   `tests/smoke/query-budget-check.sh`: เป้าหมายจริงคือ 300ms ต่อคิวรี, ใน CI จะขัดข้องอย่างเด็ดขาดที่ 2000ms แดชบอร์ดนี้ใช้ตัวเลขเดียวกัน — ไม่ได้สร้างงบประมาณใหม่ แต่ใช้สิ่งที่มีการบังคับใช้อยู่แล้วใน repo
8. **รูปแบบการแทรก CSS ที่มีอยู่นั้นไม่ได้มีการบันทึกเป็นเอกสาร (undocumented)**
   พาเนล 9999 ของ Andon (พาเนลข้อความ `<style>[class*="-panel-container"]{...}</style>`) ไม่มีรายการใน `GRAFANA_DESIGN_SYSTEM.md` จากข้อกำหนด "ห้ามใช้ Grafana CSS ที่ไม่ได้บันทึกไว้" แดชบอร์ดใหม่นี้จึงมีการแทรก CSS เป็น **ศูนย์** — การจัดรูปแบบทั้งหมดผ่าน native JSON config ของ Canvas panel (การเติมสี, เส้นขอบ, รัศมีมุม, ข้อความ) ซึ่งสามารถตรวจสอบได้จากการตั้งค่าแดชบอร์ด ไม่ใช่ CSS ดิบที่แทรกเข้ามา ช่องว่างเดิมของ Andon ไม่ได้รับการแก้ไขที่นี่ (อยู่นอกเหนือขอบเขต — มีการตั้งค่าสถานะไว้ ไม่ได้รวมเข้ากับงานนี้อย่างเงียบๆ)

## ช่องว่างของเกณฑ์การยอมรับสองประการ (บันทึกไว้ตามการตัดสินใจของผู้ใช้, ไม่ได้สร้างขึ้นเอง)

- **ข้อมูล / board_id ต้องไม่ซ้ำกัน**: ไม่สามารถทำได้จริงตามที่ระบุ — คอลัมน์จริงไม่มีข้อมูล ถูกแทนที่ด้วย `log_id` (มีข้อมูลจริง, ไม่ซ้ำกัน, ครบ 100%) และแสดงป้ายกำกับอย่างตรงไปตรงมาใน UI ว่า "Event ID" ไม่ใช่ "Board ID"
- **พนักงานคุมเครื่อง / รู้จัก SLA**: ไม่มีเกณฑ์หรือเป้าหมาย SLA อยู่เลยในระบบนี้ (ตรวจสอบแล้วในช่วงต้นเซสชันนี้: แดชบอร์ด MTTA/MTTR พบว่ามีการรับทราบ (acknowledged) การแจ้งเตือนเพียง 0 จาก 782 รายการตลอดอายุการใช้งาน และไม่มีตารางหรือค่าการกำหนดค่า SLA ในสคีมา) แดชบอร์ดจะแสดงเวลาที่ผ่านไปจริงนับตั้งแต่เกิดการแจ้งเตือน (ฟิลด์เดียวกับที่คำนวณใน Action Queue ของ Andon) โดยใช้ป้ายกำกับที่ชัดเจนว่า "Elapsed" ไม่ใช่ "SLA" หรือ "SLA compliance"

## การออกแบบ Panel

**ไฟล์**: `monitoring/grafana/dashboards/manufacturing/ims-ldi-factory-digital-twin.json` (ไฟล์ใหม่เท่านั้น)

**แถบด้านบน — ระดับผู้บริหาร (C-Level), ดูได้อย่างรวดเร็วในหน้าเดียว, <5 วินาที**:

| สถิติ | แหล่งที่มาของคิวรี | นำมาใช้ซ้ำจาก |
| ---------------------------- | --------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Fleet Availability %         | กองเครื่องจักร LDI ที่ลงทะเบียนและเปิดใช้งาน, รายงานผล และ ทำงานอยู่ | Andon panel 1, ตามต้นฉบับทุกประการ |
| Active Critical/Major Alarms | `ldi_alarm_lifecycle`, status ≠ RESOLVED                        | Andon panel 2, ตามต้นฉบับทุกประการ |
| Not-Producing count          | เครื่องจักรที่กำลัง ALARM+IDLE+NO_DATA (ตัวแทนผลกระทบการผลิต) | คิวรีใหม่, การจำแนกสถานะแบบเดียวกับไทล์ต่อเครื่องจักรของ Andon, แบบรวบรวม (aggregated) |
| Environmental Compliance %   | อุณหภูมิ 20-24°C และ ความชื้น 50-60%RH, ทั่วทั้งกองเครื่องจักร | Andon panel 3, ตามต้นฉบับทุกประการ |

**Canvas — 5 บล็อกโซน, 10 โหนดเครื่องจักร**:

- สีพื้น (Fill color) = สถานะเครื่องจักร (`0/1/2/3` → NO_DATA/IDLE/OK/ALARM), ใช้โทเค็นสีและคิวรีเดียวกันกับ repeat tiles ต่อเครื่องจักรของ Andon (`v_ldi_machine_latest_full` - เขียนทับด้วย active-alarm)
- ป้ายกำกับ = machine_id + MO ปัจจุบัน
- ความคืบหน้าของบอร์ด = `board_no/total_board` จากแถวข้อมูลล่าสุด
- ป้ายแจ้งเตือน (Alarm badge) = จำนวน Critical/Major ที่ทำงานอยู่สำหรับเครื่องจักรนั้นๆ (รูปแบบเดียวกับ Andon panel 2, กำหนดขอบเขตสำหรับ `eqp_id` เดียว)
- เป้าหมายการคลิก = `/d/ims-ldi-machine-snapshot/...` ด้วยรูปแบบพารามิเตอร์ URL เดียวกันที่ใช้อยู่แล้วในตาราง Action Queue ของ Andon และลิงก์เจาะลึกของ Manufacturing (`var-machine_id`, `var-factory`, `var-mo`, `var-event_time_ms`, `from`, `to`)
- Tooltip = เจ้าของ (การจับคู่หมวดหมู่→ทีมงานที่ใช้อยู่แล้วใน Action Queue ของ Andon), Elapsed (เวลาที่ผ่านไปจริง, ระบุป้ายกำกับอย่างตรงไปตรงมา, ไม่ใช่ "SLA"), Event ID (`log_id`, แทนที่ `board_id` ที่ไม่มีข้อมูล)

**คำอธิบายสี (Color legend)**: องค์ประกอบคำอธิบายแบบคงที่บน Canvas ที่จับคู่แต่ละสีพื้นกับชื่อสถานะ ซึ่งตรงกับโทเค็นใน `GRAFANA_DESIGN_SYSTEM.md` §2.1 — ใช้โทเค็นเดียวกับที่ใช้ในส่วนอื่นๆ ของ repo นี้ ไม่ใช่ชุดสีใหม่

## เกณฑ์การยอมรับ — การตรวจสอบย้อนกลับ (Traceability)

| ช่องทำเครื่องหมาย | ตรงตามเงื่อนไขโดย |
| --------------------------------------- | ---------------------------------------------------------------------------- |
| C-Level: สถานะการผลิตภายใน 5 วินาที | แถบด้านบน, 4 สถิติ, มองเห็นภาพรวมได้ในครั้งเดียว |
| C-Level: เครื่องจักรที่มีปัญหา | สีของโหนดบน Canvas + ป้ายแจ้งเตือน |
| C-Level: ผลกระทบต่อการผลิต | สถิติ Not-Producing count |
| C-Level: ความเสี่ยงด้านความสอดคล้อง | สถิติ Environmental Compliance % |
| Operator: เครื่องจักรแต่ละเครื่องต้องทำอะไร | ป้ายกำกับโหนด = MO ปัจจุบัน |
| Operator: การแจ้งเตือนใดที่ต้องจัดการ | ป้ายแจ้งเตือน, การคลิกผ่าน |
| Operator: เจ้าของ (Owner) | Tooltip, ใช้การจับคู่เจ้าของที่มีอยู่ซ้ำ |
| Operator: SLA                           | **ช่องว่าง** — แสดงเป็น Elapsed (เวลาที่ผ่านไป), ไม่ใช่ SLA (ดูด้านบน) |

## Performance Validation (ก่อนที่จะถือว่าเสร็จสิ้น)

1. `node tests/lint/dashboard-linter.js` — ไม่มีข้อผิดพลาดใหม่ (0)
2. `node tests/lint/query-budget-linter.js` — ทุกคิวรีโหนดของ canvas มีรูปแบบเป็นค่าล่าสุด (`LIMIT 1`/`DISTINCT ON`), ไม่มีคำเตือนเรื่อง range-scan
3. `bash tests/smoke/query-budget-check.sh` — ทุกคิวรีใช้เวลาต่ำกว่า 300ms ในทางปฏิบัติ (ขัดข้องอย่างเด็ดขาดที่ 2000ms)
4. การเรนเดอร์จริงผ่าน Grafana render API ด้วยพารามิเตอร์ของ production kiosk (`kiosk=tv&autofitpanels`, 1280x720) — ใช้วิธีการพิสูจน์หลักฐานเดียวกับที่ใช้ตรวจสอบการเปลี่ยนแปลงของ Andon Board ในเซสชันนี้ — ยืนยันว่าไม่มีการเลื่อนหน้าจอ (zero scroll), โหนดทั้ง 10 โหนด และแถบด้านบนสามารถมองเห็นและอ่านได้ชัดเจนทั้งหมด
5. `node scripts/generate-dashboard-inventory.js` — สินค้าคงคลังยังคงซิงค์อยู่ (แดชบอร์ดใหม่, จำนวนเพิ่มขึ้น 1)

## อยู่นอกเหนือขอบเขตอย่างชัดเจน (Explicitly out of scope)

- 3D Digital Twin (แผนงานในระยะต่อไป, ไม่ใช่สเปคนี้)
- การแก้ไขแถวทะเบียนอุปกรณ์ที่ไม่มีอยู่จริง 13 แถว
- การเติม `board_id` จริงในไปป์ไลน์การนำเข้าข้อมูล
- การกำหนดเกณฑ์/การตั้งค่า SLA จริง
- การเปลี่ยนแปลงใดๆ กับ `ims-ldi-manufacturing.json` หรือ `ims-ldi-operator-andon.json`
- การจัดทำเอกสาร/แก้ไขการตั้งค่าพาเนลแทรก CSS ที่ไม่ได้บันทึกไว้ซึ่งมีอยู่เดิมใน Andon (ระบุว่าเป็นช่องว่าง, แต่ไม่ได้แก้ไขที่นี่)
