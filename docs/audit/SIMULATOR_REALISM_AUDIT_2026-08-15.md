# Simulator Realism Audit (P1, Reliability Test Suite)

> Full re-run of `LDI_ALARM_FIDELITY_AUDIT.md`'s methodology (2026-08-11) against the current live dataset. Every number below is a fresh live query, not a re-citation of the 2026-08-11 figures. Classifications use the taxonomy: fixed recipe/setpoint, normal variation, controlled drift, transient fault, rare fault, simulator artifact, actual defect.
>
> Dataset window: 2026-08-13T08:22:54Z → 2026-08-15T04:52:29Z, 41,153 `ldi_data` rows, 787 `ldi_alarm_log` rows.

## Headline finding: the original audit's #1 problem is fixed, not documented anywhere as fixed until now

| Parameter                              | 2026-08-11 OOS rate               | 2026-08-15 OOS rate | Change          |
| -------------------------------------- | --------------------------------- | ------------------- | --------------- |
| Vacuum (`air_vacuum`)                  | 26.99%                            | **0.02%**           | Fixed           |
| Temperature                            | (combined into 23.26% env figure) | **0.02%**           | Fixed           |
| Humidity                               | (combined into 23.26% env figure) | **9.85%**           | Partially fixed |
| PE/JE (`abs(pe_1)>10 OR abs(je_1)>10`) | 44.93%                            | **0.68%**           | Fixed           |

**Downstream effect, also verified fresh**: the original audit's #2 finding ("91.4% of alarms are condition-driven, inverted from a real plant's noise-dominant profile") has also reversed. Condition-driven codes are now **19.3%** of all alarms (152/787), noise codes **80.7%** — a realistic, noise-dominant profile, exactly the shape the original audit said was missing. This wasn't independently fixed -- it's the mechanical consequence of the telemetry recalibration: condition-driven alarms fire off out-of-spec telemetry, and telemetry stopped being chronically out-of-spec.

Neither fix is referenced in this repo's git history under a commit message that says "telemetry calibration" or similar (not exhaustively searched, but not found in the specs/audits this session has touched) -- this improvement predates this session's own tracked work and was previously undocumented. Recording it here closes that gap.

## What this audit did not do

- Did not re-run the full 10-section structure of the original `LDI_ALARM_FIDELITY_AUDIT.md` (burst/flood behavior, `related_log_id`/`match_type` correlation semantics, top-30-Critical-code rationalization, cross-dashboard consistency, color-token consistency) -- those findings are either already independently re-verified elsewhere this session (debounce: `SPEC_ALARM_HYGIENE_COMPLETION.md`; Critical alarms: `READ_ONLY_AUDIT_2026-08-15.md`; dashboard naming: fixed in commit `f39afa9`) or not revisited. This pass focused on the specific parameter list requested (scan_speed, vacuum, thickness, PE, JE, temperature, humidity, power, vibration, alarms, severity, machine variation, temporal correlation), not a full audit re-run from scratch.
- Did not modify any simulator code or config in this pass -- audit only, per the taxonomy-classification deliverable. The one real, actionable finding (humidity recalibration) is a candidate fix, not applied here.
- Did not investigate _why_ vacuum/temp/PE/JE got fixed but humidity didn't -- whatever change recalibrated the others isn't identified (no matching commit found in a non-exhaustive search). Worth a follow-up if the humidity fix is prioritized, so the same mechanism can be reused/extended rather than re-derived from scratch.

## Recommended next step (not done here)

Recalibrate humidity's noise band or OOS threshold the same way vacuum/temp/PE/JE evidently already were, following the same "any simulator modification must include baseline evidence, root cause, physical/process rationale, expected behavior, before/after evidence" discipline this program has used for every other fix. Given the machine-specific pattern (3 of 10 machines affected), the fix likely needs to target whichever process-type profile those 3 machines share, not a single global constant.
