# LDI Alarm Severity Guide

> **Audience:** process engineering, QA/audit, SRE/operations, plant management.
>
> **Provenance:** the severity tiers, color mapping, and compliance scope below were checked directly against the live database, `dashboard-linter.js`'s approved token list, and real dashboard JSON value-mappings on 2026-08-10.

---

## The 4-tier severity scale

`public.ldi_alarm_ms_code.severity` is constrained to exactly 4 values (`CHECK` constraint):

| Severity     | Color token      | Hex       | Meaning                                                                                                                                                                                                                      |
| ------------ | ---------------- | --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Critical** | `critical`       | `#EF4444` | Highest severity — immediate response.                                                                                                                                                                                       |
| **Major**    | `warning`        | `#F59E0B` | Significant fault, needs prompt attention.                                                                                                                                                                                   |
| **Minor**    | `severity-minor` | `#EAB308` | Lower-impact fault. Deliberately a different shade from Major's amber so the 4-tier scale stays visually distinguishable at a glance — see `GRAFANA_DESIGN_SYSTEM.md` §2.1.                                                  |
| **Warning**  | `accent`         | `#3B82F6` | Lowest of the 4 tiers — informational/advisory. Maps to the _accent_ blue token, not the semantically-named `warning` amber token (that one is already claimed by Major) — a real, deliberate mapping, not an inconsistency. |

**Live severity distribution of the 19 simulator-active alarm codes** (2026-08-10): 7 Major, 11 Warning, 1 Minor, **0 Critical**. No Critical-severity code is currently generated by the simulator — that's a fact about the current simulator's fault-injection scope, not a claim that Critical alarms can't occur (the full imported catalog in `ldi_alarm_ms_code` has far more codes than the 19 simulator-active ones, including Critical-severity entries not currently wired to fire).

## ISA-18.2 scope — precise language matters here

The severity naming and color convention above borrow ISA-18.2's vocabulary. **This system is "ISA-18.2-style," not ISA-18.2-compliant** — verified 2026-08-10 in response to an earlier claim of full standard compliance. What's real:

- The 4-tier Critical/Major/Minor/Warning naming and its dedicated color tokens.

What's **not** implemented — the actual substance of the standard:

- **Alarm states.** ISA-18.2 defines a state model (Unacknowledged, Acknowledged, RTN-Unacknowledged, Shelved, Suppressed, Out-of-Service). `ldi_alarm_log` has no ack/shelve/suppress column at all — every alarm is permanently in one implicit state.
- **Rationalization documentation.** No per-alarm rationalization record (why this alarm exists, its consequence, operator response) exists.
- **Alarm performance KPIs.** No alarms/operator/10-min tracking, no % time in flood, no "bad actor" analysis.

If a stakeholder-facing document ever needs to describe alarm management, say **"ISA-18.2-style severity taxonomy,"** not "ISA-18.2 compliant" or "using the ISA-18.2 standard." (ISA-**101**, a separate standard for HMI design, is correctly and narrowly claimed elsewhere for the Operator Andon Board's kiosk layout only — not affected by this note.)

## Where severity is used

- **Andon Board / alarm tables** — every alarm-facing panel across the LDI dashboards renders severity with the color mapping above (`dashboard-linter.js` Check 15 enforces token compliance at commit time).
- **RCA correlation** — severity is not a factor in the Lift/Confidence calculation itself (see `LDI_RCA_GUIDE.md`); RCA correlates alarm _category_ (by code, mapped via `v_ldi_alarm_category`) against process parameters, independent of severity tier.

## The alarm code catalog

`public.ldi_alarm_ms_code` (columns: `alarm_id`, `alarm_type`, `alarm_code`, `alarm_msg`, `alarm_detail`, `severity`) holds a real historical export (1,820+ codes) — far more than the 19 the current simulator actively generates. See `docs/operations/ALARM_PLAYBOOK.md` for the practical, simulator-active subset with first-response guidance, and `tests/lint/alarm-sync-linter.js` for the CI gate that keeps the simulator's generatable codes in sync with this master catalog.
