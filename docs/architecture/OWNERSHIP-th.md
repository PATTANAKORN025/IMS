# สิทธิ์ความเป็นเจ้าของ Repository (Repository Ownership)

> อ้างอิงจาก `docs/architecture/IMS_MANUFACTURING_PLATFORM_V2.md` ส่วนที่ 4 (ยืนยันเมื่อ 2026-08-10): repository นี้**จะยังคงเป็นแบบ single-repo** — การแยกเป็นแบบ multi-repo ถูกปฏิเสธอย่างชัดเจนเนื่องจากไม่มีเหตุผลที่เหมาะสมสำหรับ repository ขนาดนี้ซึ่งมีเจ้าของเพียงคนเดียว เอกสารนี้ระบุถึงขอบเขตของไดเรกทอรี/โดเมนภายในที่ถูกบังคับใช้โดย `.github/CODEOWNERS` เพื่อที่เจ้าของคนที่สองในอนาคตจะมีขอบเขตการส่งมอบงานที่ชัดเจนแทนที่จะใช้เครื่องหมายดอกจัน (wildcard) แบบครอบคลุมทั้งหมด

## ทั้งสองโดเมน

| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **สิ่งที่ครอบคลุม**       | ภาพรวมของ NOC, AIOps และการพยากรณ์ความจุ, การเจาะลึกทางวิศวกรรม (Engineering Drill-Down), การตรวจสอบระดับเมตา (Meta-Monitoring) — เซิร์ฟเวอร์และอุปกรณ์เครือข่ายที่ถูกดึงข้อมูลผ่าน SNMP, ตัวแพลตฟอร์มส่วนกลางเองที่รวมถึง TimescaleDB/PgBouncer/Grafana/Prometheus/Alertmanager | ข้อมูลโทรมาตรและการแจ้งเตือนที่เกี่ยวข้องกับการผลิตของ LDI — ศูนย์สั่งการการผลิต (Manufacturing Command Center), ระบบ Andon สำหรับผู้ปฏิบัติงาน, การวิเคราะห์ข้อมูลทางวิศวกรรม & SPC, ข้อมูลสแนปชอตของเครื่องจักร (Machine Snapshot), ความพร้อมของข้อมูล (Data Readiness), ภาพรวมสถานะของฝูงเครื่องจักร (Fleet at a Glance) |

**ส่วนที่ใช้ร่วมกัน ไม่ได้เป็นของโดเมนใดโดเมนหนึ่ง:** `database/` (การเปลี่ยนแปลงระดับสคีมา เช่น โครงสร้างของ `public.devices`), `.github/` (CI/CD), ไฟล์ที่มีความละเอียดอ่อนด้านความปลอดภัย (`.env.example`, `docker-compose*.yaml`, `SECURITY.md`), `nodered_data/flows/alerting.json` (การส่งมอบการแจ้งเตือน ซึ่งอ่านจากทั้งสองโดเมน), และ Grafana Library Panels (โฟลเดอร์ `IMS` — คอมโพเนนต์ที่ใช้ร่วมกันในแดชบอร์ดของทั้งสองโดเมน ซึ่งถูกเตรียมการผ่าน `scripts/provision-library-panels.sh`) ไฟล์และส่วนต่าง ๆ เหล่านี้ยังคงอยู่ภายใต้ความเป็นเจ้าของที่ระดับ repository ซึ่งใช้เครื่องหมาย `*` ใน `CODEOWNERS` โดยไม่ได้ถูกตีกรอบเฉพาะเจาะจงที่โดเมน

## การบังคับใช้ (Enforcement)

ไฟล์ `.github/CODEOWNERS` คือเวอร์ชันของการบังคับใช้สำหรับขอบเขตนี้ — บรรทัดที่กำหนดขอบเขตโดเมนซึ่งถูกเพิ่มลงไปในไฟล์นั้น (เมื่อ 2026-08-10) จะมีความเฉพาะเจาะจงกว่าบรรทัดแบบทั่วไปของ `/nodered_data/flows/` และจะมีความสำคัญมากกว่า (CODEOWNERS ใช้กฎการจับคู่บรรทัดสุดท้ายชนะ/last-match-wins) สำหรับไฟล์ที่มันครอบคลุม เอกสารนี้อธิบายถึง _เหตุผล_ (why); ในขณะที่ `CODEOWNERS` คือ _สิ่งที่_ (what) GitHub จะใช้ตรวจสอบจริงๆ หากทั้งสองมีความขัดแย้งกัน ให้ถือว่า `CODEOWNERS` มีอำนาจเหนือกว่าและเอกสารนี้ล้าสมัย — ให้ทำการอัปเดตเอกสารนี้ และไม่ใช่การแก้สลับทางกัน

## เหตุใดจึงเป็นขอบเขตนี้ แทนที่จะเป็นการแยก Repository (repo split)

การแยกการจัดเก็บโค้ดออกเป็นหลายๆ repositories (แยกระหว่าง repository ของ `infra-monitoring` และ `manufacturing-monitoring`) เคยได้รับการพิจารณาและถูกปฏิเสธอย่างชัดเจน: เนื่องจากมันจำเป็นต้องแบ่งโครงสร้างพื้นฐานที่ใช้ร่วมกัน (Docker Compose stack หนึ่งตัว, อินสแตนซ์ของ TimescaleDB หนึ่งตัว, อินสแตนซ์ของ Grafana หนึ่งตัว, ระบบแจ้งเตือน Node-RED ที่ใช้ร่วมกัน) ข้ามขอบเขตของ repository ต่างๆ โดยไม่ได้ให้ผลประโยชน์ในด้านการปฏิบัติงานเลยที่ขนาดของ repository ปัจจุบันและความเป็นจริงที่มีเจ้าของเพียงคนเดียว — ซึ่งจะมีต้นทุนในการโยกย้ายระบบจริง (ประวัติของ git, ระบบ CI, เครื่องมือสำหรับการ deploy) โดยที่ไม่ได้ประโยชน์อื่นใดเพิ่มเติม หากทีมขยายตัวจนทำให้แต่ละโดเมนมีเจ้าของที่เป็นอิสระจากกันอย่างแท้จริง และมีรอบการปล่อยซอฟต์แวร์ที่แยกจากกัน เมื่อนั้นจึงจะสามารถกลับมาพิจารณาโครงสร้างนี้อีกครั้งได้ แต่ไม่ใช่ในปัจจุบันนี้
